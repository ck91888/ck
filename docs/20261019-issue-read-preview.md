## 分层诊断和改动

- **列表 API**：原来 `COUNT + SELECT *` 两次串行 DB 调用，分页前按创建时间排序；无逐行附件或详情请求。列表只显示短标题，却传输完整描述、反馈和备注。协同列表现在显式请求 `list_summary`，返回所需字段及最多512字符的标题来源，计数与分页选择在同一次 D1 batch 内执行。完整接口默认兼容，详情保留全文，搜索仍查完整字段；同创建时间增加 ID 排序保证跨页稳定。既有状态索引用于状态查询，排序可能使用临时 B-tree；没有证据支持另加索引或改变搜索语义。
- **详情 API**：每个处理轮次串行查询工时段。现在两次 batch 读取问题/轮次/追加要求，再读取三类历史附件和所有相关工时段，重用原工时计算。使用既有附件、job 索引及 JSON ID 集合，避免超过绑定参数数量。无业务缓存或历史工时写回；附件归属、时间线、实际工时与自然跨度保持原值。页面随后原有的 `sop_issue_adopt`、`sop_get` 流程仍保留，未把这两个请求的等待冒充为详情 SQL 改善。
- **列表读取交互**：筛选/分页新请求取消旧读取，离开页面取消读取，旧结果不能覆盖新筛选。8秒后显示等待时间，60秒只读超时显示失败和手动重试；HTML/损坏 JSON/未读完响应不再一律归因“域名问题”。详情读取同样有超时。没有自动写入重试，也不会将失败渲染为空列表。
- **原图请求**：原照片卡片直接以完整文件 URL 作为小图 `src`，20张1MB图片即20MB并发读取。小于等于256KB且进入视口的图片现在最多同时读取两张；大图和未知大小等待明确点击。打开图片显示已收到字节、等待、超时/权限/404/服务错误/解码失败及重试、下载原图、关闭。完整响应解码后显示，避免把未传完的上方条带当成完整照片。没有生成低质量副本或缩略图；选中的原图仍需下载完整字节，实际单张速度仍受网络影响。
- **浮层与生命周期**：独立网格布局约束横/竖图，`object-fit: contain`，关闭按钮与原图下载始终可见；键盘关闭和焦点返回可用。关闭/离开取消在途读取，清理 object URL；同一详情短暂复用已读取图片，并限制大图缓存数量、总字节和解码像素。超过24MB的预览明确提示使用原图下载，原文件下载不受此预览限制。原有上传上限20MB不变。
- **附件地址/权限/MIME**：URL 仍为同源私有文件接口，没有签名 URL 失效机制；有效会话及附件所属问题的权限在服务端核验。修正旧 `issue_handle` 指向 run ID 时被误拒绝的路径，旧 `job` / `ops_job` 问题照片按真实所属问题部门核验。不存在关联、草稿、未登录和跨部门继续拒绝。`/api/file`、`/file` 和 `v2_attachment_get` 旧入口保留。响应仍 `private, no-store`、`nosniff`，不设公共缓存。旧空/octet-stream MIME 的图片只在浏览器依据光栅文件签名并成功解码后显示；不更改存储对象或信任 HTML/SVG。
