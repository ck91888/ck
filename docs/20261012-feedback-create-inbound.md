# 从计划外卸货详情新建入库计划

范围：基于已发布的 `4b98631bc02c464a315ba802ab8bc2fe4f60a774`，仅在 PR #7 的 `upgrade/sop-safe-rollout-20260917` 测试分支独立实现。不合并 main，不发布正式环境，不导入或修改线上业务数据。

## 使用入口

协同中心 `/002` → 现场反馈 → 已完成的计划外卸货详情，提供“新建入库计划”和“关联已有入库计划”两个选择。

“新建”打开标准入库计划表单，带入原任务的真实实收数量及单位、原反馈内容和备注。原记录为 1 托时保持 `pallet: 1`；不转换为 1 箱。客户／唛头混合自由文本保留为原备注并提示客服确认客户，不自动匹配或填写正式客户。业务分类和原单没有的信息由客服补齐，外部入库号及作业资料沿用标准表单。

原卸货完成时间和实收证据展示为来源信息，人员信息随原任务保留。取消或返回仅关闭新建草稿，不创建计划、不改变源反馈；普通新建表单不继承残留来源。已经关联的反馈指向既有入库计划。

## 保存与历史

通过标准 `v2_inbound_plan_create` 的 `feedback_context` 保存，在同一事务中完成新建及原卸货关联。`sop_feedback_link_create_preview` 只读检查源记录并提供预填信息；最终保存重新校验来源及版本，不能依赖页面预查。

复用原卸货任务及现有反馈／卸货关联表，不复制或重建人员计时、现场产出和附件。实际数量来自服务端读取的原任务证据；后续状态沿用现有真实卸货、理货上架及作业规则。来源追溯采用 `ck_feedback_plan_links` 与 `ck_unload_plan_links`。

并发新建、关联已有计划、旧入口转正和网络重试均不得为同一反馈创建多张计划。保存失败保留可重试表单；迟到响应不得清空另一张正在编辑的草稿。办公室授权角色可操作，现场和只读角色不能使用该写入能力。
