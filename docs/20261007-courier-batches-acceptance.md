# 快递收货批次验收（仅测试环境）

批次基线：PR7 draft 分支 `upgrade/sop-safe-rollout-20260917`，`265fd873784f7a0c1f570433b9b9a936997accd2`。三处界面纠错基线：`8c0f916f3e9346dca2787f5cc2f7926b30a3af70`。核验远端 main 仍为 `4671f49b9dd74c729e738abbe1440223bdf6af0f`。本轮发布标识：`20261007-courier-ui-flow`。

## 使用

1. 现场执行 → 快递收货。先扫描已签到的操作员工牌，确认实际参与人员和主操作员后派工。一次派工一个扫描批次，编号为韩国日期加当日流水，例如 `2026-10-07-01`；99之后为100。
2. 点选所属后连续扫描运单。八个归属按钮显示本批对应所属的后端实时件数，总件数、最近收货和办公室明细均由实际保存的收货记录计算。
3. 返回菜单、刷新或换端后，从现场首页原任务或快递收货的未完成批次列表继续；每次重新进入须扫描本批操作员工牌。多名已分配人员使用同一批。
4. 调整人员沿用现有派工规则。保留人员连续计时，新增人员从保存时加入，离开只关闭本人参与。全员退出时仍可由原派工人或管理员收尾。明确“完成本批”且服务端确认结束后自动回现场执行首页，清理本页输入、轮询和返回栈；取消、失败或结果未核实保持原页。其他端完成后提示并停止扫码，已完成旧页不能继续保存。
5. 协同中心 → 到仓快递按批列表；点明细查看所属汇总和逐件运单，分页查看、修改所属、改号、交接仍沿用原功能。按运单筛选会取消默认日期限制。
6. 总工作台保持原模块卡片布局。查询位于协同中心 → 到仓快递的批次列表，复用原单号筛选，不增加第二个搜索框。查询定位匹配批次，打开明细先显示并高亮匹配运单，可切换本批全部或仅匹配并分页；清空筛选恢复当天列表。历史真实收货保留“历史无批次”查询、首次人和时间，不回填虚构批次。重复运单保留首次记录、首次批次和原所属，不转入当前批。

## 10月7日三处界面纠错

用户实际截图反馈总工作台搜索位置、独立快递派工弹窗和完成后留页不符合原意，已明确确认本轮修正范围。原先通过的隔离测试把总工作台搜索位置和完成后留页当成预期，因此不能用于证明这些交互符合用户意图。

- 快递派工与原作业派工调用同一 `CKNativePeopleDialog`，复用原 `CKPeopleFields`、`CKPeoplePicker` 和 `ck-workflow` 容器/主题。原作业部门、预计分钟、人员选择返回值及借调逻辑保留。快递不新增无关部门或预计分钟输入，仍用原批次请求。
- 去掉共用工牌字段的硬编码测试人员示例，改为中韩“工号|姓名”。空人员或未选主操作员时快递开始按钮禁用；添加、重复、移除主操作员、重新选择、可见反馈、取消、Escape和重开使用同一人员选择状态。
- 派工弹窗左右对称、可滚动，按钮至少44px；主按钮森林绿，取消为次按钮，双语换行和人员徽章按现有组件显示。每次续批的工牌确认沿用原身份校验，只使用统一容器布局。
- 完成API返回明确completed才回001首页；响应丢失时先读批次状态，确认completed再跳，读失败或仍未结束保持原页等待核对/重试。重复完成锁定，清空本页状态和导航栈，清除旧courier入口查询参数；再次打开已完成批会返回现场首页。其他端已完成的旧页面停止轮询/相机，禁用扫描和管理按钮，显示完成提示。
- 不改后端批次编号、人员计时、权限、工牌核验、运单去重、真实业务数据、其他业务处理、认证、部署配置或生产。

## 实现边界

- 增量新增 `ck_courier_batches`、`ck_courier_batch_items`、`ck_courier_batch_requests`，按需初始化；不改写历史收货。
- 使用现有 `sop_records` 派工、实际人员参与段、工牌签到核验及派工可见性；未新增角色、授权配置或登录路径。只扩展原已授权的快递请求操作。
- 批次流水、整组派工和请求去重在一个 D1 batch 事务内提交。并发创建不会重号或遗漏部分人员，失败不占流水。完成及人员调整沿用版本保护。
- 收货保存事务内再次核验批次状态、扫描人的活跃参与、签到/休息/在职状态以及当前派工访问权。完成、签退或移除与扫码竞争时，以实际提交顺序决定结果；不会提示成功却没有保存记录。
- 运单全局唯一保持不变。采购优先校验、采购库存入账、关联入库进度、运单更正保护、附件与打印流程仍使用原处理链。
- 跨午夜继续旧批保留旧编号；新派工采用新韩国日期。登录与当天签到规则保持原状，跨日登录过期仍须按原流程重新签到/登录。
- 测试清理维护表清单包含新增表，只有原显式授权的清理操作才会清除；本次未执行线上清理。
