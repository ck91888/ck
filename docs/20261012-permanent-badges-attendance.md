# 长期日当工牌管理、签到扫码与派工身份提示

范围仅限 PR #7 测试分支 `upgrade/sop-safe-rollout-20260917` 和独立 staging Worker。未修改真实人员、签到、作业记录或 main。

## 长期工牌管理

`/shuju` 日当人力的长期工牌管理支持姓名/默认人力公司编辑、停用、恢复、搜索和状态筛选。同名人员按不同工牌编号分别管理，不合并身份；编辑不改变 person ID 或工牌 ID，也不回写历史签到姓名、公司、时间和作业记录。

管理修改仅管理员可用，要求原因并记录操作人及前后值；独立版本表校验并发修改。停用阻止新签到、加入新作业及重新开段，数据库触发器覆盖校验与实际写入之间的竞争。既有作业可结束、本人可签退；结束休息不会自动重新开工。恢复沿用原 ID，不创建签到或自动恢复作业。

## 长期工牌签到摄像头

`/attendance` 长期工牌签到复用现有签到相机组件。扫描后查询登记资料并显示姓名、工牌编号及公司，必须再确认才签到。保留手输和扫码枪；停用卡显示停用状态，不提供签到按钮。

日当签退和职员上下班入口继续使用同一相机组件。测试覆盖权限拒绝、取消、重复帧、迟到回调、页面切换及媒体轨道释放。

## 拣货报未签到的调查边界

尚未确认原始现场故障根因，也未通过同名匹配、忽略日期或自动修改 ID 放宽签到校验。规范的合成二维码经真实解码器及 `/001` 人员选择、扫码枪 Enter、尾部 CR/LF、重复帧路径均保留完整 ID，并可正常开始拣货。

未命中当天有效签到时，界面显示本次提交的工牌编号、服务端韩国日期及查询结果；隐藏或非 ASCII 字符按字符码显示。这只是定位提示，不读取或泄露其他人的记录，也不会自动重新签到。可直接截图核对，无须导出请求凭据或 HAR。真实失败请求所使用的工牌 ID 尚未取得，不能据合成异常输入认定现场原因。

所有验收使用隔离内存数据库、合成人员和本地浏览器；不把真实姓名或工牌编号加入测试及仓库。
