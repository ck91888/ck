### 反馈创建浏览器定位及修复

- 本地原脚本及单独 4 倍 CPU 放慢起初通过；加入 150ms 接口延迟后，在原按钮定位处复现 strict mode violation，两份 `.ck-feedback-origin` 均有“查看现场反馈”按钮。再次跑原脚本也复现相同失败，失败 JSON、堆栈及截图留在隔离测试目录，未覆盖为通过结果。
- 根因：`002/app.js` 底层已有 `_InboundDetailLoad` 版本判断；三个异步外层扩展却在过期加载结束后继续向当前 DOM 追加区块。旧详情不渲染主体，仍会追加来源、单号、快递区块；来源缓存也可能被旧响应覆盖。修复三个扩展只允许当前计划及当前加载版本继续，并限制来源缓存只接收当前版本响应，没有改业务字段、数量和分页契约。
- 受控浏览器新增同单与跨单响应交错断言，要求来源和外部单号区块始终各一份，跨单时来源必须属于当前计划。初版受控脚本遇到会话层正常的同请求合并而相互等待，两次本地测试已明确终止，不计通过；改为不同只读请求 ID 以测试独立响应，未调整生产请求合并、等待时长、原按钮定位及原断言。新受控脚本完整通过一轮，旧 UI 隔离对照与最终验证继续执行。
- 增加浏览器失败诊断（加载状态、最近动作名/HTTP 状态、不含凭据），支持 `CK_FEEDBACK_CREATE_ARTIFACTS` 指定独立目录以保留每次失败；诊断不改变断言与超时。
