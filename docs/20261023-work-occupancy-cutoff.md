# 人员占用一致性与韩国时间 04:00 系统收尾

范围：仅 `upgrade/sop-safe-rollout-20260917`、测试 Worker `ck-v2-api-sop-staging` 与 `sop-test.ck91888.cn`。基线 `4a366c5d1b1a0109e41211e2d0c46fafad82f48d`；保留订单处理工时功能。不修改 main、正式配置、凭据或授权身份。

## 可验证根因

人员卡只把属于本次有效签到、且任务状态为 working/pending/awaiting_close 的未退出段显示为作业中；派工校验检查所有未退出段。因此旧班次、暂停、已完成但无法可靠收口、任务资料缺失等记录可能在卡片上表现为“未分配”，同时仍正确阻止重复作业。管理部门标记是独立的当天管理信息，不能解除任务占用。派审归属也不等于本人实际参与工时；身份仍按工牌核对，不按姓名猜测合并。

新卡片显示“占用待核实”、原任务状态及完整韩国日期时间；报错提供可核对的任务标签、开始时间和提交工牌。换单的业务拒绝后再次确认保留人员、主操作员和预计分钟；传输结果不明时沿用原请求，避免重复建任务。

真实站点在执行环境被 HTTP CONNECT 403 阻断。三张用户图均经当次 Library 支持流程及明确本机目的目录的一次重试下载失败，执行环境未读取用户图像像素。现场记录的具体起止不由此报告猜测；本报告不把合成复现当作真实业务验收。

## 04:00 规则与恢复

测试配置新增 `SOP_DAILY_CUTOFF_ENABLED=true` 和 cron `0 19 * * *`（19:00 UTC，即次日 04:00 Asia/Seoul）。`scheduled` 在服务端运行；API 入口在业务处理前补收漏跑边界。它不是聊天提醒，也不依赖有人打开页面才能在定时正常触发时执行。

每个仍未结束的执行会话按开始后首次越过的 04:00 截止。历史漏跑采用同一规则，不能把部署时刻当作真实结束。04:00 整点及之后的新会话属于下一周期，保留继续执行。缺少合法开始时间的旧执行使用最近已到达的系统边界并保留异常证据，不宣称真实作业时长。

执行任务进入专属 `system_closed`（系统强制结束、待核实）；工时段标记 `system_cutoff:unverified`，停止于规则边界。保留原始开始、原分钟、原数量、原状态和完整原行快照。暂停、无人计时和订单处理任务同样在执行层收尾。人员休息和签到事实不被伪造或自动签退；结束休息不会复活已系统结束的任务。

收尾不调用任何业务完成路径，不新增作业成果，不把入库、出库、理货、拣货、快递等单据自动验收、发货或扣减库存。借调审计保留，旧借调关闭并禁止自动归还重建原任务计时。所有快照、事件、退出和执行状态更新在同一 D1 事务中；失败整体回滚，可重试。延迟的旧请求不能覆盖系统退出、插回旧计时或直接写完成成果。

原派审员/现有授权管理员从原任务明确核对人员续作；原生、作业计划、批次、快递和订单处理复用各自续作入口，建立新段并保留旧段。多单批次仍只有一人一条批次实际计时。已有待审核成果保留，不自动批准；仅恢复审核阶段时不额外开启人员工时。无派审记录的历史执行从原业务单据重新建立后续执行。

## 待核实与补正

系统截止不是实际离岗证据。待核实段排除有效部门工时、本人实作、实际作业人时及可比效率；考勤区间内转入待核实冲突时段，不计为已核实工作。实际作业报表保留原始跨度、异常和 provisional 标识，禁止与成果形成可比人效样本。WMS 复合人效遇到相关待核实段时返回待核实，不把未核实工时排除后继续拿混合数量计算效率。CSV 保留相同异常标记，考勤 CSV 另列系统截止待核实分钟。

办公室管理员可在人员明细“系统截止工时待核实”中填写这一段的真实结束日期时间及核实依据。只能在原开始与系统截止之间补正，保留原开始和系统快照；按实际确认的结束重新计算该段，并保存管理员、依据、前后完整段和请求编号。补正幂等、并发比较当前段，不能悄悄覆盖其他核实结果；它不会完成业务任务。截止后确实继续工作应通过续作新段记录。

旧班次尚未系统收尾时，如果核实的是实际离岗，可在原签到日期使用现有“核实补卡”入口；它只关闭可证明属于该班次的个人段并保留审计。任务结束不等于离岗，不能用当前签到的休息/签退或伪造上下班时间作为解锁办法。
