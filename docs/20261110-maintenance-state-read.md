# 维护状态读取失败：只读检查与安全诊断

基线：`5642cdb5534c432b22114e1f3cc1341d4d5da433`。用户截图在卸货选单入口显示“测试维护状态读取失败，请稍后重试”。该文字唯一来自 `worker-v2/staging-entry.js` 的统一维护检查异常分支，返回HTTP 503，发生在具体业务处理前；截图不能证明存在活动重置，也不能确认数据库异常类型。

## 已证实的代码问题

旧入口先调用 `ensureResetSchema`，再读取活动状态。每个未命中初始化缓存的数据库绑定/冷启动可能先执行3条建表/索引语句；初始化异常直接拦业务，即使维护状态本身可读。

隔离复现给合成维护表正常SELECT、仅拒绝维护DDL，旧入口仍返回503，没有进入原认证。原失败日志保留。相同夹具在修复后不执行维护DDL，正确返回原认证401（没有凭此绕过登录），原合成入库记录不变。

这是确定可复现的误拦截；**尚未取得现场底层D1错误，不能断言截图一定是这个原因，也不能认为部署后一定解决平台额度或数据库可用性问题。**

## 本批改动

- `maintenanceInProgress` 对已有控制表只执行 `SELECT 1 ... LIMIT 1`；不读取维护清单、人员或错误详情，不做维护DDL。
- 不缓存“有/无活动状态”。每个正常请求重新读取，活动任务仍阻断；数据库读失败仍返回503，绝不放行。
- 只有明确缺少该控制表才沿用原有新库初始化，初始化后必须重新读取。初始化或重读失败继续阻断；其他缺表/缺列不触发初始化。
- 返回白名单错误码区分繁忙、超时、日用量、空间、结构或未知异常，不返回原D1错误、SQL、参数、凭据或业务字段。
- 正常认证、Cookie、活动维护期间的原登录分支、重置开关与start/step路由没有改变。没有合入之前暂停的重置禁用补丁，也不能据此声称旧重置流程已安全；开关关闭、已有在途清理的既有风险不在本批修复范围。

分类参考Cloudflare官方错误说明及额度说明：[Debug D1](https://developers.cloudflare.com/d1/observability/debug-d1/)、[D1 Pricing](https://developers.cloudflare.com/d1/platform/pricing/)。这些资料用于解释错误类型，不是现场发生该类错误的证据。
