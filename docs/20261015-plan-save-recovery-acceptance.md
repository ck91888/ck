# 作业计划保存反馈与响应恢复（仅测试环境）

基线为 PR #7 测试分支的 `58f3a0aeac42c8ecf107f558c5734547d134c596`。本变更不包含一人多单作业的未完成实现，不更新 main、正式 Worker 或真实业务数据。

## 行为

办公室新建库存作业、从入库建立或追加作业时，提交编号在附件上传之前生成。上传显示当前文件、文件序号、字节进度和服务器确认阶段；保存与结果查询显示阶段及用时。附件等待上限 60 秒，提交等待上限 30 秒，单次查询等待上限 8 秒。浏览器停止等待不代表后台取消。

提交成功但响应不完整时，客户端先只读查询原编号。未确认时明确显示“保存状态未知”“查不到不等于未保存”，保留原输入、文件、已上传附件和冻结的提交内容。用户选择继续原提交时复用同一编号和内容，后端事件唯一键与事务保证只创建一次。不会全局重试写 API。

关闭窗口会保留当前页面内存中的草稿；重新打开相同来源可继续。明确选择“放弃此草稿”才清空尚未提交的草稿。提交状态未知时禁止放弃后换编号新建。成功完成后清除恢复记录，下一次新建获得新编号。

输入内容、原始 File 和提交正文均不写入浏览器磁盘。sessionStorage 只保留用于查询的请求编号和账号、操作会话、来源标识。整页刷新后可查询已创建结果；若结果仍未知，刷新前的输入及 File 无法恢复，页面阻止直接换编号重建，提示先核查来源关联作业。

后端查询和幂等重放受当前账号、当前操作会话、办公室角色和当前部门权限约束。变更正文不可复用已成功编号。其他账号、其他操作会话或来源的查询返回相同的未知状态，不暴露原单详情。退出登录清理页面草稿和查询记录。

## 隔离验证

使用真实 Worker API、内存 SQLite、内存 R2 和本机 Chromium 的合成客户、人员、图片和单据；不读取或修改测试站现有业务记录。

- `tests/need-create-receipt.test.mjs`：无分组双 PNG、无数量和预约；已创建结果查询；重复、并发及不同正文的同编号提交；不同账号、操作会话和来源的权限隔离。
- `tests/plan-save-resilience-browser.mjs`：第二附件上传失败、已接收字节后客户端超时、提交成功丢响应、事务仍在处理中超时、关闭重开、原请求迟到与同编号重试并发、上传中关闭、双击、整页刷新查询、账号内存隔离和 390px 手机布局。
- `tests/cargo-create-resilience-browser.mjs`：入库内嵌多卡、库存独立作业和入库追加分组保持原有资料路由；内嵌导航取消语义保留；独立窗口关闭上传后保留并恢复一次。
- 全部 `tests/*.test.mjs` 回归使用 jsdom 30：1088 通过，0 失败，0 跳过；两组真实浏览器验收全部通过。

本变更修复可复现的客户端静默等待、响应丢失恢复及重复风险。未取得用户现场失败请求的浏览器网络记录或 Worker 日志，因此没有确认此前 `Failed to fetch` 的实际网络根因。执行器直连测试站仍受代理 CONNECT 403 限制；发布核验使用测试分支精确提交和 Cloudflare 构建状态，不绕过代理限制。
