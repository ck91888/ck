# 职员每日出勤排版修正

基于 `e50d10cb091cb664f9fa3a65aad07126432f5295`，只更新 PR #7 测试分支。用户反馈上线后的九列表格堆叠双语长句、按钮断行、行高过大、作业列头与内容错位，本轮保留后端统计与业务数据，只重构呈现。

## 页面变化

- 桌面归为职员、现场状态、作业数字、上下班、出勤/休息、操作六组。派单、本人参与、参与任务已完成、本人实作工时各占稳定数字位置；姓名不再夹带按钮。
- 明细与补卡在同一操作区，颜色区分、尺寸一致，每种语言各一完整行。无现场任务采用短灰色状态，不再使用撑高行的黄底长句。
- 保留数据看板原双语模式。中文主标签和韩文次标签分层，其他页面原有语言切换机制未改；缩短标签不改变统计含义。
- 容器较窄时改为双列或单列卡片，320px 的四项数字改为两行。表头与数字使用同一网格，覆盖旧全局列序号、字号和内边距样式。
- 明细先显示姓名、查询时点与数字；统计口径可展开，空栏目默认收起，有记录栏目默认展开。长工号与日期分别换行，关闭入口始终可用。

## 验收方法

复用原九个真实 Worker 浏览器场景，另加八组视觉尺寸：1440/1280 × 100%/125%/150%，以及 390/320px 手机。使用一次性 Chromium 配置，通过浏览器设置 API 设置真实页面缩放；同时断言 `innerWidth` 和 `devicePixelRatio`，未使用 CSS transform 或截图缩放。截图直接从 Chromium 合成器按页面实际像素范围采集，避免自动化工具在原生缩放时按 CSS 坐标错误裁切。

合成数据包含长中韩姓名、较长历史部门文字和中韩/字母混合任务号；仅在进程内 SQLite 数据库构造。每个尺寸实际打开明细、展开口径、打开补卡并取消，检查业务表快照不变。视觉检查涵盖完整页面、列表局部、明细顶部及长任务内容，另检查表头中心、普通行高、按钮每种语言的行数和点击范围。

项目持续视觉验收要求已加入 [20260921-design-and-attendance.md](20260921-design-and-attendance.md)。

## 实际截图观察与结果

- 全量 `tests/*.test.mjs` 978/978 通过，0 失败、0 跳过（启用 JSDOM）；构建、JavaScript 语法及 `git diff --check` 通过。原刷新与看板测试按新组件选择器核对部门、现场状态和任务搜索，CSV 仍保留原任务信息。
- 1440px、1280px 原始比例：普通行实测 63.84px，四项数字与各自表头中心偏差为 0；长姓名/部门自然增加行高至约 118px，全文可见，不裁切来强压高度。
- 两种桌面宽度下的原生 125%/150% 缩放：按可用空间切换成双列卡片，标题与工具栏分行；数字、状态和两个按钮均不互相挤压。每个按钮每种语言保持一行，至少 44 CSS 像素高。
- 390px：单列卡片、四项数字横排。320px：单列卡片、数字两行两列。已实际检查完整列表、长文本卡片与弹窗顶部/任务内容，按钮均可点击，长工号和日期完整分行，页面与明细无横向裁切。
- 看图发现并修复了四类问题：旧表格样式覆盖数字字号与手机内边距；工具栏挤窄中韩标题；窄屏工号/日期不合理断行；桌面标题的 flex-basis 在手机纵向布局中制造多余留白。最后一项已补入视觉脚本的标题空白检查。
- 原九个浏览器行为场景通过，新增八组视觉场景通过；所有合成业务表在查看、展开、关闭、取消后快照一致。验收产物：`/tmp/ck-employee-layout-matrix/acceptance.json`、`visual-matrix.json` 和同目录完整截图。可通过 `CK_EMPLOYEE_VISUAL=1 CK_EMPLOYEE_ARTIFACTS=/tmp/ck-employee-layout-matrix node tests/employee-workday-browser.mjs` 在构建后复验。
