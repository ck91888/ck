# CK SOP 升级：试运行候选版本

基线：main `4671f49b9dd74c729e738abbe1440223bdf6af0f`。
此分支未合并、未部署；原网址、生产 Worker、数据库和附件桶未做修改。

## 已实现的代码

- 独立负责人工作台：扫码录入工牌、主操作员、预估时间、提前分配与实际开始分开；人员增减、暂停、操作完成、审核、返工与授权代办。
- 操作人员时间段写入原 `v2_ops_job_workers`，派工人不会自动计入操作人数；原看板仍可读取时间段。审核等待不继续计作业时间。
- 作业需求：入库/出库关联，一项需求只允许一个在执行任务；审核后反馈、部分数量关联出库、剩余货物去向。
- 试点范围内开启自动生成后，新建需要库内操作的出库计划与统一作业需求同事务保存；原出库详情显示关联要求。旧出库单不会批量转换。
- 问题点：对无进行中处理轮次的旧问题显式接入；客服随时追加说明/修改要求，逐版本确认；旧入口不能再修改已接入的问题。变更在工作台轮询提示，关闭页面不保证通知，紧急变更仍需企业微信联系。
- 出库日期总清单：Excel/CSV追加、冲突提示/跳过/替换、撤销留痕、已核对条目改量重新核对、改日期原子迁移、11/13/16及追加轮次、异常复核、最终交接与重新开启。
- 旧核对批次可在旧任务全部收尾后接入；保留原条码、有效扫描数和异常记录，原日志不删除。
- 管理看板：当前任务/人员、合格成果按作业及单位分别汇总、韩国日期工时切片、待办/数据待核实、日报CSV。新版范围明确标注；历史WMS看板继续保留，不直接生成奖金评分。
- 所有新写入记录操作者和前后内容；版本冲突及请求重试保护；新旧任务同时争用同一人员时阻止重复记时。

## 配置与权限

`worker-v2/wrangler.toml` 保持原样；不要用它部署测试。
使用 `worker-v2/wrangler.sop-staging.toml`，其D1占位符必须替换为新建的测试数据库ID。测试R2也必须独立。
测试旧接口所需 ADMINKEY、VIEWKEY、OPSKEY 只配置测试值；新增个人凭证通过Worker secret `SOP_USERS_JSON` 配置，禁止写进网页或提交仓库。
结构示意（非可用凭证）：

```json
[{"id":"人员唯一ID","name":"姓名","role":"dispatcher","departments":["bulk"],"key":"通过安全渠道设置个人随机授权码"}]
```
角色：manager（跨部门管理）、dispatcher（派工）、reviewer（审核）、service（客服需求）、viewer（只读）。
部门：bulk大货、direct_ship代发、import进口。实际岗位名单应由经理确定后配置。

## 测试与发布顺序

1. 独立环境准备：新建测试Worker、D1和R2，配置测试身份；测试数据使用脱敏副本或虚构数据。
2. 基础结构：测试环境先初始化原有v2结构，再执行 `migrations/20260917_sop.sql`。迁移仅增加两张表、索引和保护触发器，不删除/重写原记录。
3. 设置 `sop/config.js` 的 SOP_API 为测试地址；不使用生产地址。`shared/sop-rollout.js` 仅在测试副本设 enabled:true。
4. 在测试环境运行任务全流程、旧任务收尾、原003采购/领用回归；检查总任务数、有效扫码数、人员分钟和操作成果均可追溯。
5. 完成浏览器、手机、并发、真实规模与故障恢复验收，再定切换窗口。优先选择业务较少时段，不要求全仓停工。
6. 上线前取得生产D1一致性导出/可恢复点，验证备份可恢复到另一数据库；记录Worker版本、Git提交和前端版本。备份不能只保存代码。
7. 先发布兼容后台，新功能开关保持关闭；确认旧端扫码、任务结束和003仍正常。
8. 维护窗口执行附加迁移并校验，然后设置 SOP_UPGRADE_ENABLED=true；只为试点人员配置凭证。
9. 新版前端使用独立 `/sop/` 地址。先小范围新任务试用；旧任务从原入口结束，不强制换到新任务、不重置计时。
10. 若启用出库自动关联，再设 SOP_AUTO_OUTBOUND=true 与 SOP_ROLLOUT_DEPARTMENTS=bulk；切换点之后的新计划进入统一需求。不要提前开启自动生成却不交付新版入口。
11. 确认一整个业务日的派工/审核/交接与数据后，再扩大代发和进口。每组长当日核对漏记、未结束、待审核和重复任务。
12. 旧版自助开工入口应在试点业务完成覆盖后收口。在完全收口前，每日同时检查新旧看板，不能仅凭新版未记录判断员工无工作。

## 停用与回退

- 出现问题先将 SOP_ACCEPT_NEW=false、SOP_AUTO_OUTBOUND=false，停止新增新版任务/自动需求；已开始的新任务仍从新版收尾。
- 不直接关闭 SOP_UPGRADE_ENABLED，不直接回滚至完全不认识新数据的旧Worker。新任务存在期间必须保留兼容接口与保护逻辑。
- 新版存量收尾后可隐藏入口。代码回退选择包含兼容补丁的已验证版本。
- 不在持续营业时用旧数据库快照覆盖现有库；否则会丢失备份后的真实业务。数据错误先查事件并做前向修正。
- 如确需整库恢复，另行安排所有写入暂停、备份后增量保全与核对，不能当作普通代码回滚。
