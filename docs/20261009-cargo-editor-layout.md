# 资料范围分组编辑器排版修复

基线 `0cfc137f906e7ee0022886e5b36dea438c262175`，发布标识 `20261009-cargo-editor-layout`。仅测试分支，字段、校验和业务流程不变。

根因是外层 `.ck-work-plans fieldset` 两列规则作用于内层资料组 fieldset，内层四列货物字段被挤进左半边，其他控件又各占一个外层网格位置。本次明确资料组 fieldset 使用块布局，再为货物信息、操作要求和文件区设置自己的布局。

- 组名与宽箱唛范围同排；箱数旁放一唛一箱确认，区分标记说明位于输入框下。
- 操作名称和要求分区对齐；较长说明放在字段下方，不再撑高标题。
- 文件选择、已选文件状态和无需资料原因归在同一区域；长文件名正常换行。
- 删除按钮为紧凑的次级危险操作。新建和详情使用同一编辑器；窄容器自动单列。
- 手机新建移除重复外边距和内边距；320px下原货物明细表固定列宽、防止原表撑宽页面。

验证：真实构建002/001页面，31箱六组和超长文件名；新建、保存后详情分别检查1440/1280桌面、1280视口下1.25/1.5根级CSS缩放、390/320手机，共12个编辑器截图。校验整页无横向溢出、控件不越出卡片、宽屏字段上沿对齐、删除按钮宽度适中，实际查看桌面、150%缩放、手机和详情像素。缩放测试使用Chromium CSS zoom，不宣称测试了浏览器工具栏缩放操作。

`tests/cargo-layout-browser.mjs` 随后继续跑完整31箱创建、部分审核出库、暂停、余组新版确认恢复及6箱2托出库。全量689通过，0失败0跳过。日志 `/tmp/ck-layout-full-tests.log`、`/tmp/ck-layout-release-browser.log`；截图 `/tmp/ck-cargo-e2e/layout-*.png` 均为隔离合成数据。未写线上业务数据，最终提交和Cloudflare成功证据见发布报告。
