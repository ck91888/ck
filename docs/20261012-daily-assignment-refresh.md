# 日当工牌大小写准入、当前作业与现场首页刷新

范围：基于 `85868e95245ea50e538135a0cf81b493017aa03e`，仅 PR #7 测试分支 `upgrade/sop-safe-rollout-20260917` 和独立 staging 站点。验收使用合成人员、内存数据库及本地构建页面，不调整真实考勤或作业记录。

## 大小写准入根因

现场补充截图中，作业成员的完整系统 DA 工牌是小写，签到看板对应完整编号是大写，仅大小写不同。真实 Worker API 的隔离复现得到同一症状，不需要假设签到更正：

1. 系统签到生成大写 `DA-YYYYMMDD-8位十六进制` 编号。
2. 原人员扫描模型只分隔编号与姓名，原样保留小写编号。
3. `guardAttendance` 的大小写敏感前缀识别漏掉小写，未执行签到查询；数据库原 `GLOB 'DA-*'` 防线同样漏掉。
4. 作业成员和拣货参与记录按小写保存；日当看板按大写签到编号精确查询，显示未分配、零工时。
5. 同一编号的大写变体还能绕过已有小写段的占用检查，签退也会漏关原小写段。隔离空签到数据库使用小写 DA 编号也能开工，证明这是准入漏洞，并非只有显示问题。

修复统一前端、API 和数据库的受管工牌准入。大小写等价只适用于合法日期及八位十六进制后缀的系统 DA 格式；DAF、EMP 和自定义编号保持精确身份，大小写变体不能绕过签到防线。历史小写作业以唯一的合法签到身份兼容读取和处理生命周期，保留原主键、原编号和原审计，不批量改写历史。

身份冲突、无合法签到或旧班残留不能自动合理化；不自动补签到、不补写工时、不按姓名合并。新增、调整主操作员、休息恢复、暂停恢复及旧接口均需重新遵守对应准入约束。数据库升级必须在既有触发器的隔离副本上验证。

## 独立复现的同日补卡问题

在真实 Worker API 的隔离数据中，同一完整工牌先签到、开始代发拣货，再由负责人将当天签到时间更正到作业开始之后，现场仍保留该人的活动作业段，但日当看板会显示未分配且部门工时为零。旧逻辑把所有早于当前签到时间的未结束作业段一律视为上个班次，未识别同日签到更正。

同一判断还影响个人休息和签退：原活动段被关闭为零分钟，休息记录没有保存可恢复的原任务。修复需要保留原作业时间证据，区分当前成员状态和有效签到区间内的工时，不把签到前时间加到出勤统计。

补卡例外必须有同一签到记录、同一工牌的更正审计证明该段原本属于当天签到区间，并排除已确认签退边界；不能仅凭同一天或同名接纳遗留段。原始作业段仍记录真实开始至结束的跨度，日当统计另按有效上下班时间裁剪。例如作业 09:10—12:00、核实后的签到为 09:47，原始作业段保留 170 分钟的事实，日当有效代发工时为 133 分钟。本轮不改其他报表的原始工时口径。

现场首页的在途任务卡另有刷新缺口：只在进入首页时读取一次；另一端调整人员后，旧卡片仍可能停留。日当看板已有独立自动刷新，两个页面因此可能显示不同读取时点的数据。

## 身份与现场核查边界

人员按完整工牌身份关联，仅系统 DA 编号采用上述限定格式的大小写等价。DAF、职员工牌、自定义编号及同名不同编号互不归并；管理部门标签不等于实际任务或工时。首页卡片人员来自原始未结束成员段，不将派工快照中的历史名单算作在岗人员。

补充截图及大小写合成复现支持本次准入根因；同日补卡仍是单独发现的通用漏洞，不作为该实单必须经历过的事实。核查具体记录时，可只读打开任务的“调整人员”查看姓名旁完整工牌编号，再取消；在日当看板刷新后查看该人的明细及作业时间段。无须保存人员、重新派工、修改签到或导出请求凭据。部署后的实际站点状态仍需现场只读复核。

## 验收要求

- 小写系统 DA 正常扫描与大写身份一致，不产生第二身份；未签到的大小写编号在新旧 API 和数据库防线均被拒绝。
- 既有小写成员正常关联合法签到；保留原始段、休息、签退及暂停恢复完整，重复及身份冲突不得造成双倍统计。
- 同日签到前移、后移及连续更正后，当前有效成员与有效工时分别正确；不扩展到签到前。
- 跨日遗留段、重新签到、同名不同工牌保持隔离；已结束、移除、暂停及休息人员不冒充正在作业。
- 休息、恢复、签退与补签退保留原始成员段，不把真实当日参与错误关闭为零。
- 首页仅在可见、可安全更新时刷新，回到前台重新读取；不打断任务或编辑，不丢失草稿。
- 旧响应不得覆盖新页面状态；读取失败保留已有数据并提示过时，不假报暂无任务或未分配。
- 实际 `/001`、`/shuju` 页面连接隔离真实 Worker 验收后，执行全量回归并核对部署提交。
