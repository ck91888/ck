# 订单处理值班工时

基线：测试分支 `upgrade/sop-safe-rollout-20260917` 的 `a8c6d1508867056cd9a3c879d7aae2210e5b01a9`。发布标记 `20261022-office-order-duty`，仅目标 `ck-v2-api-sop-staging` / `sop-test.ck91888.cn`。

协同中心 `/002/` 增加一个「订单处理」入口。通过已有职员资料查找实际工牌，服务端取登记姓名和原部门；不按办公室共享账号或手填操作姓名推定实际劳动者。开始、暂停、继续、结束复用现有任务、人员工时段和审计事件。开始/继续要求韩国当天有效签到、已结束休息且没有其他在计任务。

同人办公室与现场工时互斥。已有装卸借调会停止该人的办公室时段，装卸完成后按原借调资格和状态归还；暂停后也可转现场作业，现场未结束前不能继续办公室计时。借调未归还时不能直接结束源值班。通用清理不能把借调中的无人计时源任务自动完结。

请求回执与任务修订号在同一事务内保存。重复点击及响应丢失重试沿用原请求；页面重载读取服务器状态，保留未确认请求供显式重试。工时来自服务端人员段，暂停和借调间隔不计入；不读取浏览器焦点或单据修改时间推算活动。

员工日报明细标明仅工时，CSV 增加「订单处理分钟（仅工时）」。按实际作业日期的员工、部门及任务报告/导出保留职员原部门；`quantity_state=time_only`，不报数量缺失、不采集产出、不计算数量效率。已结束时段按韩国日界裁剪，未结束时段继续沿用现有报告的排除政策；页面进行中显示仅用于查看计时状态。历史数据、原登录、会话、角色及持续访问配置保持原样。

不增加接单/审单/制单/改单/交接细分计时、单号、数量、成果指标、WMS 导入或派工成果看板。
