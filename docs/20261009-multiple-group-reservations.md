# 同一资料组多条出库计划

发布标识：`20261009-multiple-group-reservations`。基线 `290017745440744b4761fe7cb5866f8b23f5f59a`，仅提交 PR #7 测试分支 `upgrade/sop-safe-rollout-20260917`。不合并 main，不修改正式或真实业务数据。

## 使用方式

- 同一资料组可以连续添加多条出库计划。新增按钮始终位于列表末尾；折叠标题显示序号、本次数量和日期。
- 每条独立填写本次数量、单位、日期、运输方式、去向、PO 和交接说明。数量/单位未知时显示待确认，不默认分配全组；可以只分配一部分，余量留待以后安排。
- 本次箱唛子范围选填，不要求拆作业组或重复上传资料。填写时校验属于本组且不与其他有效预约重复；已明确一唛一箱时校验子范围与箱数一致。
- 每条在首次保存时创建独立正常出库单。编辑、确认成果和实际出库沿用原单号及 ID；单独取消保留订单和历史，释放该条占用。
- 同单位、同总量的箱数成果审核后按各条明确数量确认。例如本组10箱，预约4箱和6箱，分别分配4箱和6箱，不向两单各复制10箱。
- 箱变托或实际成果总量变化时，按真实审核成果逐条确认。例如6箱加工成2托，两单各确认1托；确认前不能装货，不自动换算箱托。

## 数量及历史保护

`cargo-capacity.js` 统一累计同组有效预约与已确认分配，同一订单只计一次。已出库分配持续占用；取消仅释放对应未出库订单。作业版本、出库版本、实际作业状态和同事务审计共同防止并发超占及失效页面覆盖。

已确认但尚未实际装货的数量修改保留旧分配快照，并记录正常出库单变更及仓库确认标记。仅修改运输信息不重建分配快照。正在装货、暂停装货、已出库或已取消的订单不能通过预约接口改写。

原单预约及旧整组分配继续可读、可执行，不批量迁移历史数据。文件继续按本组与合法公共资料继承，已确认分配使用固定版本快照；新预约不包含其他作业或其他组文件。

## 验证结果

全部使用本机隔离 SQLite、R2 内存对象、虚构职员及真实构建页面/Worker 路由，没有在线写入验收样例。

- 最终全量：709项通过，0失败、0跳过；相关专项21项通过。
- 真实 Chromium 链路：10箱同时预约4+6，两单分别实际出库；先预约并出库4箱，再新增余6箱；丢响应重试不重复建单；原单改为5箱后超额2箱被拒绝，取消后重新安排6箱并完成出库；已出库快照保持不变。
- 6箱变2托：两条未知数量/单位预约在确认前均不能装货，分别确认1托后两张原单各实际出库1托，超额确认被拒绝。
- 四入口：新建入库作业卡、独立库存作业、已有入库追加、作业详情，均支持多条预约；覆盖多卡隔离、上传失败、退出取消、整单预约冲突、逐条编辑取消。
- 36组/72条草稿：中间移除一条后保留71张正确对应的出库单、日期/PO和37份实际文件。1440、390、320宽度无横向溢出，新建及已保存页面新增控件保持列表末尾。
- 附件：办公室/现场实际下载内容与原上传一致，仅包含本组及公共文件；既有无分组资料完整现场至实际出库回归通过。
- 数量专项：并发预约、并发确认、取消释放、未分配余量、旧单兼容、实际成果少于预计、子范围重叠/越界及组范围变更保护。

测试入口：`tests/cargo-multi-reservations.test.mjs`、`tests/cargo-multi-reservation-browser.mjs`、`tests/cargo-multi-layout-browser.mjs`、`tests/cargo-reservation-resilience-browser.mjs`。本机日志位于 `/tmp/ck-multi-*-final.log`，截图位于 `/tmp/ck-cargo-e2e/multi-*.png`。
