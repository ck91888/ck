## 根因及复用范围

整单 `shippingCapacity` 在审核前只读取单一来源计划量（或旧的单一 `shipping_basis`），入库同步建单还要求出库单位与来源单位相同。因此10箱来源不能直接明确预约作业后1托。已审核后的 `shipping_output` 更正支持混合包装，但不能用于作业前预计包装。

审查了 `cargo-groups` / `cargo-processes` / `cargo-execution` / `cargo-capacity` / `cargo-reservations` / `cargo-allocation` / `cargo-shipping`：分组已有独立实际产出、审核/版本、预约与最终分配，且允许多个工序共享来源箱唛。继续使用原分组模型，不将其误当成整单箱托换算。原实际构成更正及其审核、历史出库关联、取消释放、缺失/已发货单占用逻辑继续保留。

## 使用与数量口径

在入库新增作业的“预计包装与来源箱范围”，或既有作业“出库安排”/出库预约页的同名区域，明确填写：

- 本作业的来源箱数和范围。范围以本作业清单内部箱序表示，从1至来源总箱数完整覆盖；箱唛对应关系写入包装依据。每一段不能重叠、遗漏或越界；余散箱须明确单列。
- 每段预计的独立托数及独立散箱数。例如1–10箱→1托；或1–8箱→1托、9–10箱→2散箱。没有固定箱托比率，也不解析备注、打托工耗或纸箱耗材来猜测。
- 包装依据。仅办公室客服/管理员维护；直接转发及分组继续原流程。

复用 `shipping_basis` JSON：添加 `sources`、聚合 `components`、来源数量/单位、版本、操作者、时间和依据。每段来源只进入同一预计包装池一次；各出库预约再从这个池按单位占用，不为每条预约复制整批来源。预约链接记录 `shipping_basis_version`，现有 SOP 事件保存不可变前后状态。修改预计包装不能低于已有各单位预约；旧箱预约须先逐单核对调整或取消，不能直接将10箱等同1托。

入库、作业、预计包装、可选出库同步建单共用原 D1 原子事务。后补预约和各单位数量限制复用 `reserveShipping`、SOP版本冲突、事件幂等和批量建单；取消只释放对应出库的包装占用，已发货或缺失引用不释放。原始 `planned_quantity/planned_unit` 保留来源口径。来源计划数/单位更改会重新校验已记录的来源范围。

这是**同一整单作业内部**的来源分区和包装占用账；没有建立跨独立作业/分组的全仓库存唯一箱序，也不阻止同一货物进入后续加工工序。分组/多工序的共享来源与独立产出仍由原模型管理。

## 实绩与装货

作业反馈新增可选的“实际独立出货包装”：实际独立散箱和实际独立托数，混合时填写全部；留空继续使用原单一成果量。保存为 `result.shipping_components`，与工作量/耗材分开。反馈和审核都按各单位核对当前有效预约；不足不能通过，不会生成合格成果或放行装货。现场表单拒绝后保留输入。

审核后容量优先采用已审核实际构成/更正，忽略预计包装。单单及合车装货开始/完成继续校验当前实际产出、有效占用、作业审核、单据状态及版本；取消预约在核对实际占用时排除。合车校验批量读取取消状态，避免每条预约增加独立查询。实际装货数量继续受原各单应装数量校验。

旧单不迁移或回填预计包装，没有新字段时按原来源/原成果/旧 `shipping_basis` 运行。原打印、附件、工时、报表实现未改；共享文件中的变动仅为数量/单位界面及校验。
