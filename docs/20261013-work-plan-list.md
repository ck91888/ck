# 作业计划列表日期、筛选与来源核查

仅测试环境 `ck-v2-api-sop-staging` 的 `/002` 协同中心 → 作业计划启用。发布基线为 `ff0c054a54e27622ac414c6f432c52f2d95773d8`，保留该版本的入库筛选紧凑排版。系统「现场反馈」页不在本次范围。

## 日期含义

| 列表项 | 数据依据 | 缺失或特殊情况 |
| --- | --- | --- |
| 实际到仓（卸货完成） | 已完成卸货／入库作业中的实际收货数量；分组卸货使用该入库计划自己的结果及卸货完成时间 | 不使用建单、更新时间、人工补齐时间；无结果时可使用明确的卸货完成字段并标注来源 |
| 实际理货入库 | 已完成作业中实际理货数量及结果时间 | 直进直出显示「无需理货上架」；历史补齐且无真实结果显示「实际日期未记录」 |
| 预计到达 | 明确关联的入库计划预计到达日 | 库存作业没有入库关联时显示「无入库关联」 |
| 最早待出库 | 明确关联、未删除且未取消／出库／完成的出库计划中最早的有效计划日 | 全部未填日期单独提示；已结束计划在历史中显示原计划日期，不冒充实际出库时间 |

所有日期筛选以韩国日期为准，起止两端都包含。实际到仓、理货与预计到达匹配任一来源记录；待出库范围匹配本批最早待出库日期。多次实际作业展示首末日期范围，展开「日期与单据来源」可核对每条记录、业务单号、韩国时间与关联单据。

## 查询与返回

客户、作业／关联单号、作业状态、待出库安排与四种日期范围可以组合。服务端在权限允许的完整分组集合中先筛选，再计数和分页；不会只查已加载的前 50 批。无结果时保留筛选并提示清空重查。日期起止颠倒在界面提示并阻止请求。

「查看作业单」进入原有本批作业明细。返回列表或从入库来源详情切回作业计划，会恢复当前用户在本标签页的筛选与页码。查询失败保留原来的输入和列表；迟到的列表响应不会盖掉详情页。
