# 新建问题点附件

基于 `8ca2e2a677d80563e029fa84a4ad24a625b625c5`，仅更新 PR #7 测试分支；发布标识 `20261012-issue-create-attachments`。未修改 main、正式部署、真实业务或考勤记录，未新增数据库迁移。

## 用户入口与呈现

`/002/ → 问题点沟通 → 新建问题点` 在描述下方、提交上方增加附件。可多选照片与 PDF、XLS/XLSX、CSV；拍照只在主动点击时打开。每个文件不超过20MB，每个问题最多20个，展示照片缩略图或文件名、大小、状态，支持移除。

提交时上传。上传失败保留文字、已选文件及成功上传的文件，重试仅补传缺失文件；创建响应丢失后保持同一提交草稿、锁住待确认内容，重试返回同一问题。提交成功或返回离开清空当前页面草稿，新建另一问题不沿用旧附件。进行中的上传／提交禁止页面内切换，移除已上传文件会释放草稿名额。

办公室“原始附件”区提供照片放大及文档下载；创建时间线只记附件数量并指向原始附件区，避免重复展示文件。现场问题详情沿用原照片预览，文档名改为有权限的下载链接。旧仓库反馈上传、记账、追加、作废、只读历史均保留。

## 存储、幂等和权限

- 复用现有私有 R2、`sop_records`／`sop_events` 的版本保护与 `v2_attachments`。草稿按已验证的办公室账户及当前登录会话绑定，客户端不能指定存储对象地址或上传人。
- 每次文件上传按固定请求ID、内容SHA-256及文件名核对；草稿在同一 D1 batch 内发布问题和所有附件，版本冲突阻止并发重复建单。取消、移除与创建共享版本保护，已发布附件不能再被草稿清理删除。
- 草稿对象不允许从文件下载入口获取。已关联文件经现有登录下载入口返回，保留 private/no-store 和 nosniff；新增原始附件不允许绕过草稿接口直接写入。
- 原始附件及处理轮次附件按问题业务部门检查现场会话的授权范围；未登录、签到点及受限会话越权均拒绝。现有现场登录默认授予的业务范围没有改变，员工所属部门不等于会话授权范围。
- 服务端验证大小、扩展名、MIME与实际文件签名／结构：图片标识与必要头尾、PDF头尾、XLS容器标识、XLSX ZIP目录与工作簿条目、CSV文本。XLSX限制目录条目数与声明展开总量，拒绝宏条目。此校验不声称替代病毒扫描或完整Office/PDF解析。
