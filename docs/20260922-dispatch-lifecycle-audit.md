# 派审员管理逻辑：前后端排查与修复

日期：2026-09-22；发布标识：`20260922-dispatch-lifecycle-audit`。

## 业务基准

派审员分配实际操作人员，管理人员加入、离开和交接，核对产出后结束任务。派审员浏览页面不产生自己的操作工时，也不能默默替一名操作员退出。个人休息和签退只结束本人参与；全员转出后，需要填写产出的任务仍可重新打开收尾。

## 已定位并修正

| 问题 | 原因与修正 |
| --- | --- |
| 多人临时卸货没有完成按钮 | 原界面只允许最后一名操作员完成。派审员现在可核对实收后一次结束整组人员；重新打开现场反馈任务保留正确的临时卸货入口。 |
| 多计划同车卸货重复派工风险 | 连续扫描多个计划或外部入库号，同计划去重；一车一个工时任务，各计划分别核对实收。每个计划的查询、编辑保护和入库状态使用完整关联，不重复计算人员工时。详见同日多计划卸货文档。 |
| 装货提示完成，实际还在待收尾 | 后端仍等待其他人员自行退出。派审员完成时原子保存产出、结束所有参与人员、更新原出库计划。重复结束不重复记产出。库内操作完成进入待客服更新出库计划。 |
| 拣货创建后提示“不记录工时”，完成只退出一个人 | 页面统一为扫描单号、分配人员、开始计时、结束整趟。每名参与者正确关联本趟单据；结束操作同步关闭人员、单据和趟次。 |
| 拣货总工时随单据数倍增 | 原汇总叠加每人每单的重复时间；改用实际人员参与段。同一人做两张单30分钟仍计30分钟。 |
| 校验失败却已停止一人计时 | 先校验空实收、负数、无效数字、缺失外部工单客户和产出，再执行结束；入口与任务类型不符时拒绝写入。 |
| 暂时离开、临时插单默认操作主操作员 | 原页增加“调整人员”；留任人员连续计时，移除人员结束当前段，新增人员开始新段。调人去装卸货也先明确修改人员。全员转出保留待收尾任务。 |
| 返回菜单后把旧任务带进其他业务页面 | 导航返回首页或业务菜单时清除当前页面任务上下文，服务端任务继续，可从在途任务重新进入。 |
| 已结束任务的时间随查看刷新变化 | 人数校正不再更新业务完成时间。 |
| 扫已有任务的单号，新的多人派工实际只加入一人 | 开始前识别已派工的原任务，引导打开原任务调整人员，避免部分加入。 |
| 不同进口取送货班组合并为同一任务 | 派审员新建取送货使用独立任务；其中一组结束不影响另一组。 |

人员变更有请求去重、版本校验、审计和数据库事务。任务结束与人员变更并发时，变更不能把已结束任务重新打开。休息、签退及其他任务占用约束继续有效。

## 排查范围与回归

检查现场执行、协同中心、耗材物品、数据看板、签到及共享界面的调用关系；检查 Worker 路由、派审、入库、快递、考勤、职员导入、统计与测试清理模块。65个非压缩 JavaScript/模块文件（含测试及旧入口）通过语法检查。第三方压缩库未做逐行审计。

| 模块 | 本轮验证重点 |
| --- | --- |
| 现场执行 | 原生任务的多人完成、人员变化、菜单返回、临时卸货、拣货、外部作业、取送货、退件、核对及通用作业 |
| 协同与入库 | 多计划卸货、A1/A2逐单完成、免理货分类、需求可先于预约创建、原计划状态和数量回写 |
| 快递 | 格式限制、所属更正、原地改号、首次扫描信息、原计划撤回与正确计划匹配、混合货物收齐约束 |
| 考勤与职员 | 签到、补打、实际休息、签退、部门归属、个人工时不分摊、导入整批校验与身份保留 |
| 看板 | 人员参与段统计、完成时间稳定、多人多单不重复计时、原始结果保留 |
| 耗材与测试清理 | 共享登录及页面初始化；采购与快递的边界；测试清理隔离、备份、重试与并发保护回归 |

`node --test tests/*.test.mjs`：130项，125通过，0失败，5项既有可选 DOM 用例因未配置对应运行时跳过。本轮新增13项生命周期测试，覆盖数据库故障回滚、重复提交、并发、整组转出、复用单号及三人结束。

本地浏览器使用真实 Worker 路由和隔离 SQLite 数据验证：三人临时卸货 → 原页换人 → 数量备注不丢 → 完成；两单两人拣货 → 整趟完成；全员转出 → 首页保留任务 → 再打开仍可结束。五个业务模块均可正常打开。多计划连续扫描与分计划实收流程在先前同日修复中完成浏览器验证。

## 发布与数据边界

本次仅发布测试分支。未替用户填写实收、结束真实测试任务或批量修正历史工时。旧任务可使用新页面继续管理。已有派审记录在原表中保留，新增人员变更保护触发器按需建立，不重写历史参与段。

这是一轮按业务调用链的排查与回归，不等于所有输入组合、网络故障和硬件环境已穷尽。PDA、扫码枪、N51实体打印及仓库规模压力仍需现场验收；不将本地模拟结果当成这些设备已经通过。
