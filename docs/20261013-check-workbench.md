# 2026-10-13 核对派工与连续扫码工作台

目标分支为 `upgrade/sop-safe-rollout-20260917`，基于已发布的 `c033ac93bac69e7758202ce2e2b8b06efe509870`。仅独立 staging 开关启用，不修改 main 或正式业务数据。

## 行为

- 现场选择日期清单或旧批次后，先扫描实际人员工牌，指定多人、主操作员、用工部门及预计分钟。沿用当前签到、占用和派工校验。
- 派工后保留一页工作台：操作员、托盘、条码、累计摘要、最近日志和结束作业。支持扫码枪逐字符输入后 Enter；每次提交保存当时的人员、托盘、任务与请求编号。
- 队列串行提交。同条码的多件实物分别计数；同一请求重试不重复计数。失败保留首条与后续队列，暂停自动发送，允许原请求重试。页面重开后可从首页任务卡恢复队列。
- 当前批次包含此前历史扫描；任务结果只记录本任务成功扫描次数，并明确标记为整任务记录，不记成个人产量。历史清单、日志及参与时段保留。
- 整任务暂停/恢复、个人休息及人员调整复用已有生命周期入口。休息或离岗人员不能继续扫码；结束本次核对关闭全部在岗时段。
- 现场结束日期核对作业后，日期清单仍保留，由经理或复核人员保存轮次、处理异常和最终交接。现场不可绕过派工直接扫描，不显示无权修改清单的动作。

## 一致性与权限

新增 `ck_verify_requests` 回执表，扫描回执、权威日期清单版本、事件、扫码日志与批次状态在同一事务提交。事务内再次检查任务权限、在岗人员、有效当日签到、休息、批次状态与版本；并发设备发生版本冲突时重新读取，不能留下半笔记录。相同请求编号用于其他人员、托盘或条码时拒绝。

旧批次沿用扫码日志计数；日期清单沿用当前有效条目数量。撤销条码、清单外条码和超量均记录异常。日期清单存在工作、暂停或待收尾任务时不能最终关闭，事务内也重新校验。清单变更不把仍有活动任务的批次错误改回待开始。
