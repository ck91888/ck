# 自动派审工时：开发阶段记录

基线：远端测试分支 `upgrade/sop-safe-rollout-20260917` 的 `7957cf19cba3db69f24889e0f23a79aa60029632`。开发分支：`feature/dispatch-time-auto-20261102`。未修改 main、正式 Worker、既有业务数据或真实历史工时。仓库及父目录未发现 AGENTS.md 或 .agents/skills 指令。

## 当前阶段：状态机与事务账本基础

新增 `worker-v2/dispatch-time.js` 和 `tests/dispatch-time.test.mjs`。本阶段尚未接入派单、操作、签到接口和人力看板；没有开始按钮，没有启用配置，没有给真实任务生成派审时间。新模块在未被服务端实际生命周期调用前不改变现有行为。

独立账本使用 `ck_dispatch_time_sessions`、`ck_dispatch_time_events`，不创建 v2_ops_jobs、v2_ops_job_workers、正式成果或 sop 业务派单事件，不影响操作产量和业务派单数。身份键为稳定人员 ID 与实际签到 ID；数据库唯一索引限制同一稳定人员同时只能有一个派审状态，版本触发器阻止多设备覆盖。业务写入与派审状态可放入同一批次，事务失败整体回滚；重复请求返回原结果，不重放业务 SQL。

状态模型已覆盖：首次真实派单才激活、多单只记一个人的连续区间、末单结束后待派单、亲自操作互斥、退出操作按有效签到／资格／休息／借调／未完成职责重新判断、休息和签退、显式转单从发生时刻切换、跨日与系统切日区间保留待核实。模型不会凭页面在线、共享关系或历史挂单创建职责。

锁屏、关页、心跳中断和短暂断网都不是停计依据。已移除最初基础版本里的确认有效期／心跳超时模型，不使用浏览器在线情况判定劳动。只以服务端休息、签退、真实操作及订单状态为权威。跨日或系统04:00截止仅保留临时区间并标待核实，不伪造实际下班，也不无限累积。

状态机 21 项、工时归集 8 项隔离测试通过；连同既有签到／班次规则共 56 项通过，0 失败、0 跳过。测试使用合成身份与内存 SQLite，包含多单、操作／休息交错、工时守恒、失效资格与借调不恢复、显式转单、跨日／系统切日、锁屏不截断劳动、请求重试、业务事务失败、多设备版本竞争、跨工牌单人唯一计时及不生成操作任务／成果。

## 独立工时归集能力（未接入实际看板）

`attendanceReport` 增加可选派审时段参数；不传该参数时原调用与返回结构不变。有效派审时间单列为 dispatch，仅分配原未归属区间，已有操作与休息优先保留，重叠派审不重复计入。多人／多单重复时段按个人并集合并。待核实切日区间单列，不能当成有效劳动或拿去自动补休息。

`shiftAttendanceReport` 把派审时间加入已归属劳动基数；签退补休息仅使用余下未归属时间，保留实际签到后、规则取整上岗前已经发生的劳动。新增 8 项测试覆盖守恒、重叠、补休息不足、待核实、身份不符、旧调用兼容和长时间无页面活动仍计时。

仍未为任何实际签到附加派审段，没有后台自动开计时或开始按钮。共享单首次处理与跨日续单的激活规则仍未选定，切日后不会凭资格变更、休息结束或页面状态默默恢复旧职责。

## 已读取的既有逻辑与后续接入点

- attendance.js：人员段只来自实际参与表；休息／签退原子关闭参与段；人力概览和有效时段裁剪在 overview。
- daily-dispatch-permissions.js：DAF 身份及当天日当工牌关联、有效签到、部门授权与撤销；正式职员使用既有 EMP 规则。不得通过姓名推断身份。
- employee-workday.js：派工、审核、参与和成果分开，只归属可验证 actor_id；派审时间应独立展示，不能混入参与产量。
- office-duty.js：现有仅计工时模式会创建普通任务和参与段，只适用 EMP。新派审账本不照搬该入口。
- crew-borrow.js：借调出／归还与实际人员段同事务；恢复必须重新检查人员、日期、任务和权限。
- attendance-shift-policy.js：签退补休息只能转换未归属时间。接入时派审劳动必须先从未归属中扣除，并加入已归属劳动基数。

下一阶段需要：在派单／完成／取消／转单／操作参与／休息／签退事务中接入账本，服务端解析稳定身份和资格，增加单列派审时间与状态、明细、CSV、守恒核验，跑真实 Worker API 和 PC／手机验收，再交独立审核。本基础模块不能作为已完成功能发布。

## 需要总管确认的边界

1. **共享协作者处理别人的单**：A（建议）只按实际身份记录审核工作量，不因此自动开其派审计时；要接班先显式转负责人。B：首次实际审核／处理后，把该单加入协作者当天派审职责，再从该动作时刻起计；需明确原负责人是否同时继续。单纯建立共享关系均不计时。
2. **跨日遗留单**：A：新一天仅新派单或正式转单激活，签到／刷新／历史挂单均不启动。B（建议）：当天对旧单第一次明确恢复／继续处理后，只从这个动作开始计；无实际动作的旧挂单不纳入当天持续计时职责。均不回推签到时间、不补历史。
已明确的限制：不采用浏览器心跳、关页或锁屏作为劳动判定，不再提出在线超时停计选项。异常跨日／未签退按既有签到与系统切日规则保留待核实。

显式正式转单的规则已经确认：旧负责人移出该单，新负责人从交接成功时刻起算，仍须有效签到、资格和未参与其它操作；不把之前工时转给新人。本项不需要重复确认。
