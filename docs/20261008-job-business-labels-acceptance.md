# 作业显示与派审员统一验收

基线：PR #7，`b52460e00527c1cbbffb98251d50c2df1e9309db`。发布标识：`20261008-job-business-labels`。仅更新测试分支，正式版及现有业务数据不变。

## 业务显示规则

内部 JOB / SOPJOB 主键不再作为操作人员识别作业的显示内容。底层主键、关联关系、按钮参数、扫码载荷和 API 操作标识保持原样。

- 关联作业计划显示已有 ZY 号；外部作业显示原外部系统作业号，保留前导零。
- 入库、出库、现场反馈、问题处理、核对作业使用对应业务来源号码。
- 同车多计划卸货和多单装货保留全部关联单据，并可按其中第二张及后续单号查到原任务。
- 拣货显示实际拣货单清单，保留原扫描顺序及前导零；原趟次仍是同一任务。
- 快递批次保留真实批次号。
- 无来源单号的盘点、打包、整理等通用计时作业显示真实类型、用工部门及韩国时间，不编造订单号。
- 已有 RW 派工号继续保留在兼容字段和查询入口；新增规范化显示字段区分真实来源单号与通用作业，避免破坏旧列表/导出查询。
- 合法外部号码即使带 JOB-/TASK- 前缀或 WMS-UUID 形式也保留；只屏蔽已知内部标识形式及当前记录确切主键。

## 派审员来源

派审员只取该任务关联 `sop_records` 的 task/dispatch 记录保存的 `state.owner` 和 `state.owner_id`。不以当前登录操作姓名、主操作员、普通作业员、制单人或客户/店铺所属替代。未保存派审员的历史任务显示“未记录 / 미기록”。

后端复用批量业务号映射，输出 `display_business_no`、`has_business_reference`、`job_label`、`dispatcher_name`、`dispatcher_id` 及结构化作业类型/部门/开始时间。前端统一用 `CKDocumentLabels` 展示并在 HTML 边界转义。查询按唯一任务批量进行，不逐人/逐行新增任务查询。

## 已核对展示面

- 日当与职员：当前作业、明细时间轴、业务号/派审员搜索及 CSV。
- 现场：首页在途任务、继续原任务、外部作业和作业计划、退件入库、进口取送、拣货趟次/提示、任务生命周期、装卸货、人员借调与归还历史。
- 协同：按单操作列表与详情、任务列表/详情、历史记录和相关打印。
- 看板：实时人员/单据、强制退出确认、作业列表/详情、工时明细与 CSV、日报。
- 独立 SOP 源页：列表、详情、实时任务和导出；原部署路径范围不扩大。
- 原始结束原因如 `job_completed` 已转为可读中韩文。历史文本只替换可确证对应的作业标识，其他未知关联不会被冒充为当前单号。

窄屏验收另发现旧看板头部固定高度使时钟/操作区覆盖任务页签，已最小调整为可换行自适应高度；实测页签恢复可点，不改业务逻辑。

## 验证

使用完整当前源码、Node 24、内存 SQLite/D1 和真实 jsdom 组件，未操作线上业务记录。最终运行：

`node worker-v2/build-sop-staging.mjs`

`CK_JSDOM_MODULE=/tmp/ck-workforce-deps/node_modules/jsdom/lib/api.js node --test tests/*.test.mjs`

新增测试覆盖 21 种已有作业类型、真实派审员来源、无姓名降级、外部号码、重复引用批量查询、扫码和按钮参数不变、多单查询、历史时间轴、查询/导出兼容、XSS 转义及中韩文标签。原 RW 查询、拣货扫描顺序和 CSV 日期边界的回归保持通过。最终完整回归（含状态同步补丁）625 项全部通过，0 失败、0 跳过，构建及所有涉及的 JavaScript 语法检查通过。

实际 Chromium 验证使用独立虚构数据：现场真实派工接口创建 DEMO-WMS-7301，派审员为“演示派审员金”；办公室当前姓名切为“演示办公室李”，各界面仍显示原派审员。验证了实时看板、日当当前作业/历史明细、现场卡片打开与返回原任务、韩文协同列表/详情、桌面及约 485px 窄屏。历史无派审员的盘点显示真实类型/部门/KST 时间与“未记录”，无 JOB UUID 或原始结束代码。

物理扫码/打印设备、真实弱网和云端规模并发未测试。受现有访问限制，未访问线上业务页面；发布结果以对应提交的 Cloudflare Workers Builds 检查为准。


## 作业状态同步补丁

另一次用户反馈出现“现场在途作业名册有人员、考勤仍显示未分配”。对已部署 b524 源码的隔离复现确认：先打开未分配名单，再从另一设备开始合法作业，原看板没有自动重读，直到手动刷新才显示作业中。同工牌、同快照、有效签到区间的在途计时段判定保持正确。用户当时真实记录的具体原因尚未查证，不能仅凭同名推定重复签到或合并身份。

日当、职员及现场人员视图现在仅在页面可见且所选日期为韩国当天时，每15秒只读更新状态；切回页面即补刷。页面显示最后成功报告的韩国时间，失败时保留旧数据并明确提示可能过时。任何明细/编辑、导入面板或提交期间暂停自动应用，关闭后恢复，不覆盖未保存内容；保留筛选、焦点、滚动，后台/历史日期停止轮询，销毁/重建正确清理。职员后台轮询仅读取汇总，不重复读取资料与权限。

新增29项确定性刷新回归，连同完整套共625项通过、零失败、零跳过。实际浏览器模拟另一设备为同一工牌开工：明细保持打开和原内容并提示暂停；关闭后自动变为作业中，显示盘点及真实派审员；随后无手动刷新时报告时间继续推进。未更改真实业务记录、姓名归并、工时、签退或后台有效性条件。
