# 取消快递入库计划重建与到仓预提示

范围：PR #7 的 `upgrade/sop-safe-rollout-20260917` 测试分支。全部验收使用隔离内存数据库、合成单号和本地浏览器；不修改线上业务数据，不合并 main，不发布正式环境。

## 原问题与修复

`/002` 新建入库计划选择快递、填写多个单号后，已经取消的旧计划仍会提示“已关联……请先核对”。原取消接口只更新计划状态，`ck_courier_plan_items.tracking_no` 的唯一占用没有解除。仅忽略取消状态仍会撞上主键，不能解决问题。

新建或修改计划时，对可安全复用的已取消旧计划，在同一数据库事务内归档旧关联、释放活动占用并登记新关联。既有取消旧单直接适用，不需要重新取消或手工 SQL。多号中任何一个不满足条件，整批回滚；有效计划仍保留唯一占用。

原计划、货物行、附件和作业历史保留。归档保存旧关联、重新关联对象、操作人和时间；有真实快递扫描时保存当时的收货快照，复用原收货记录而不重复扫描、不编造时间。旧计划历史不会混入重建后新增的扫描。已记账、手动完成、有真实现场作业、下游出库或其他有效作业要求的旧关联继续受到保护。

当前任何关联出库单（包括已取消出库单）均要求先核对，不自动迁移下游关联。升级只以 `CREATE ... IF NOT EXISTS` 新增历史表和保护触发器，不批量重写旧业务数据；旧占用在用户实际重建且校验通过时才归档释放。

取消接口重复提交不重复追加原因；取消、现场开工和重建以提交时状态为准。已经释放占用的旧取消计划不能恢复为活动计划。

## 新建时显示实际到仓记录

快递多行输入触发只读预查，显示每个单号是否到仓、原始扫描时间（韩国时间）、扫描批次、扫描人及计划占用。旧查询返回时若输入或页面已改变，不覆盖当前结果；保存仍由服务端重新验证。

全部匹配显示“已到仓”，部分匹配显示“部分到仓 x/y”，没有匹配显示“未到仓”。计划详情使用相同进度展示。先扫描后建计划与先建计划后扫描沿用相同业务状态计算。

本次保留既有完成规则。依据 [20260922-courier-receiving.md](20260922-courier-receiving.md)“操作与联动”中记录的用户确认规则和 [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md)：无需理货上架的直进直出、整托退回、换单，快递收齐可完成入库节点；代发或有上架单号仍需实际理货上架，混合车辆货物仍需实际卸货。到仓提示不撤销这些原有要求，也不替代作业审核。

- `tests/courier-cancel-browser.mjs`：实际构建的 `/002` 页面创建、取消、冲突失败后按钮和输入保留、重新录入成功、旧附件与历史保留。设置 `CK_EXPECT_CANCEL_BUG=1` 可在修复前版本复现原故障。
