# 大货产出预填写

本功能基于远端测试分支 `upgrade/sop-safe-rollout-20260917` 的 `16ea2901b2db304ba50c111ffdbeb69cdf8cddc3`，开发分支为 `feature/bulk-output-draft-20261102`。基线已包含派审共享 `1da6da72fb70feb2bfd9a63b4f422cab421ee9ee` 和已上线照片压缩；未从共享分支另取提交，未修改 main、共享分支或线上数据。

## 使用方式

普通需求单和外部作业在派工表单旁增加“预填写产出”。只填部分字段也可点击“保存产出草稿”，不会创建或结束作业。派工后可通过“预填写／修改产出”或原“填写产出并审核结束”打开同一表单。保存后的值在刷新、重新进入、同一身份的另一台设备上恢复。

资料组在本组表单保存草稿；派工前预填归属于首道工序，界面在多工序组显示工序名称。派工后按实际任务、资料组及工序读取，前一道工序草稿不会带入下一道。整任务工耗在派工后即可预填，避免在人员、工序及资料组的任务划分尚未确定时，将整单工耗带入多个任务。

一人多单分别保存各子任务草稿，切单和刷新不会串单。保存草稿不触发首单审核释放人员、不切换工时、不创建正式成果、出库或绩效记录。原有分组提交、审核、退回及完成逻辑保持原样。结束时带出草稿，最终核对修正并通过既有严格校验后，才记录正式产出。

保存按钮显示实际保存人、时间和版本。保存失败保留当前表单输入；传输失败重试使用同一请求编号和内容。另一设备已保存或任务已变化时拒绝旧版本覆盖，用户可明确点击“重新读取已保存草稿”。已完成、取消或已提交正式成果的对应任务／资料组拒绝继续修改草稿。

## 实现与边界

- `worker-v2/bulk-output-draft.js` 提供 `sop_bulk_output_draft_read`、`sop_bulk_output_draft_save`。草稿保存在原任务／待派需求的 `state.output_drafts`；尚未派工的外部纸单使用当前派审员和准确单号共同确定的 `bulk_output_draft` 记录。
- 每次保存使用任务版本、草稿版本和要求版本；`sop_events` 保留保存前后内容、实际会话身份、时间和请求签名，原版本触发器及共享权限事务检查防止并发覆盖。原生完成和草稿保存之间额外检查任务状态与版本。
- 普通／外部表单和逐组表单复用现有字段。草稿允许空值及部分输入，仍拒绝未知字段、非法类型及负数／小数工耗。完成动作沿用原校验，不将草稿字段写入正式统计。
- 待派单仅现有经理／派审员角色可预填；实际任务沿用原负责、授权和协作权限。协作退出后及退出与保存竞争时拒绝保存。客户端不能指定保存人。
- `shared/bulk-output-draft-ui.js` 接入 `field-work.js`、`cargo-groups-ui.js` 和多单选择器的来源版本同步；构建清单包含新组件。照片处理模块未修改。
- 新流程没有自动提交、定时保存、自动审核、自动恢复人员或自动完成任务。未保存的本地输入不保证跨刷新保留。
