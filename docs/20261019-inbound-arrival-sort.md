# 入库计划按预计到达日期倒序

范围：基于 `28f624e84d650e5bf8ec6d71d83ec77a3f8223d5`，仅测试分支 `upgrade/sop-safe-rollout-20260917` 与 `ck-v2-api-sop-staging`。发布标识 `20261019-inbound-arrival-sort`。

## 行为

- 协同中心入库计划按预计到达日期降序，晚的在前、早的在后；空字符串、NULL、空白和不能解析为日期的历史值排在末尾。
- 复用现有预计到达筛选的韩国业务日期语义：日期和 datetime-local 按本地日期；带时区的时间转换为 KST 日期；兼容 YYYY/MM/DD。同一业务日期仍按原计划日期、创建时间降序，再按 ID 降序确定稳定顺序。
- 数据库在 LIMIT/OFFSET 前统一排序，前端保留返回顺序；CSV 使用同一排序表达式，在导出上限前排序。原日期、状态、业务、客户、记账、卸货日期筛选及分页限制不变。
- 不改执行候选接口及旧 required_biz_class 路径的排序，不改入库分阶段、出库资料计数或加载性能修复。不迁移 schema、不改写历史业务数据、不新增客户端全量读取。

## 性能边界

50条页面仍为9次数据库调用，明细 enrichment 仅限该页，没有新增远程查询或读取写入。保留原筛选索引；新排序在 SQLite 内使用临时 B-tree，不引入索引/schema变更。

本地合成完整请求测量：88条数据约1.7–2.2ms，新增排序差异不足0.2ms；10,000条时，未筛选约9.9→15.5ms，建单日期筛选9.4→11.0ms，状态筛选4.3→11.9ms，客户搜索5.1→6.1ms。9次数据库调用与50行响应限制保持相同。此为本地 SQLite 样本，含运行噪声，不能当作 D1、网络或线上加载时间；此次改变排序存在额外的数据库排序成本，没有宣称速度提升。
