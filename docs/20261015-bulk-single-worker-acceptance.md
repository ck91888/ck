# 大货一人多单：隔离验收

本阶段以 PR #7 测试头 `3e93c60c7a45498b9eefe577f33ab2a14f13dc06` 为发布基线，整合本地检查点 `3a4da57`，保留仓库历史完成工时修复 `58f3a0a`、保存恢复、来源数量解耦、追加预约目标与创建人显示。仅用于测试分支和 `ck-v2-api-sop-staging`。

## 实际行为

大货入口可多选需求作业单，或连续扫描外部作业单，一次派给一名实际操作员。前端扫描器与后端均拒绝零人或多人；重复单号去重。每批最多20张来源单，各来源的独立资料、工序、任务、实际成果和审核保留。分组需要不同工序时沿用各自的任务。

只有当前单计时。切单在同一数据库事务中关闭原时段、暂停原单，再打开目标单时段。等待单无计时；完成一单不代替其他单完成。重复请求、并发派工和并发切单由幂等编号、版本事件、来源占用和单人单时段约束处理。提交期间来源取消或原生任务完成，事务会回滚，不能重开完成单或部分切换工时。

个人休息只关闭当前实际时段；结束休息仅恢复仍有效的原任务。整批暂停后不会因个人休息结束自动开工，须明确恢复。更换人员仍限一人，只改变未完成单的指派并保留历史工时。取消仅撤销所选未完成且无产出的派工，保留原作业要求。

普通产出表单在批次页面内按任务保留未提交内容；切到另一单不带入原单数据。刷新或离开页面不承诺保留未提交表单，已提交成果和照片沿用原持久化流程。

“转移本批派审员”明确移交所有未完成单；已完成单的原派审和历史保留。原派审离岗后，在岗同部门派审员可从首页明确接班。转移和接班均不替换实际操作员、不重开工时时段。旧负责人失去批次操作权限。

PC 1440px 与手机390px使用相同单据列表，显示业务编号、客户、作业名和状态。人员、换人及交接操作折叠，子单不重复显示批次导航。

## 验收证据

所有验收均在本机真实 Worker、内存 SQLite/R2 和 Chromium 中使用合成数据，不操作测试站现有单据或正式数据。

- 完整 `tests/*.test.mjs`：1104通过、0失败、0跳过；jsdom30执行全部DOM测试。
- `tests/bulk-work-batch.test.mjs`：16项。覆盖人数、独立任务/成果、普通与分组/原生作业、幂等、并发、取消、休息、暂停、签退、换人、源版本变化、原生完成/来源取消竞态、派审转移及离岗接班。
- `tests/bulk-work-batch-browser.mjs`：真实多选、双击、第二人工牌拒绝、切单独立草稿、分别完成、休息/暂停/换人、派审转移、离岗接班、外部扫码去重、原生任务独立完成、分组专用附件/范围/成果/审核/收尾；无浏览器JS错误。PC与手机截图已实际查看，无横向溢出。
- `tests/native-dom.test.mjs` 的完成日期详情、修改、历史与打印通过。旧失败原因是批次保护误用于只读资料查询，向 SQLite 绑定了未定义任务编号；现仅拦截相关写操作，不影响无任务作业的只读详情。
- `tests/plan-save-resilience-browser.mjs` 保存热修验收全部通过。
- `tests/dispatcher-warehouse-browser.mjs` 仓库整理热修验收通过，原两组人员/任务未改变。
- `tests/inbound-append-independent-browser.mjs` 数量解耦、旧完成单/附件/出库保留、预约目标、PC/手机创建人显示通过；响应丢失按当前恢复流程查询原提交，无第二次创建。
