# 进口专区：当日扫描结果

基线：`upgrade/sop-safe-rollout-20260917` 的 `e3f754611f8348388106ce23625874db7bd49f5e`。父任务确认库内/退件提交 `cd7038f61e19e46e6f91da4812a82f7167235bae` 已发布后，基于该最新提交整合到本地 `import-daily-integration`；保留该提交全部24个文件的功能和测试。没有读取、改动或用于测试的线上业务数据；全部测试使用隔离合成人员和记录。

## 使用

现场执行 → 进口专区 → 当日扫描结果 / 당일 스캔 결과。选择业务日期，输入当天总量后保存；初始日期按韩国 UTC+9，查询、更正可选择其他日期。未录入显示“未录入”，有效 0 显示 0。空白、负数、小数、非数字及非安全整数拒绝保存。

已保存区显示总量、首次记录人、最近更正人、韩国更新时间与版本。展开“更正记录”可查看每次前后值；每页20条，可继续读取。最近列表展示最近30个已录入日期，列表以外可直接选择日期查询。

失败不清空输入；可重试，或点击“读取最新值”，保留输入并与服务器当前值核对后保存更正。同日重复请求不会累计。两人同时更正，只有一个版本成功，另一人收到冲突提示，必须读取并核对新版本。返回菜单再进入保留本页尚未提交内容；刷新浏览器不会持久化未保存草稿，但已经保存的值可重新查询。

## 数据及权限

- 新表 `ck_import_daily_scans`：业务日期主键，一天只有一条当前总量。
- 新表 `ck_import_daily_scan_events`：请求ID唯一，业务日期＋版本唯一；保存前后值、服务端会话记录人、时间、身份范围。历史全部保留，不自动回填。
- 两表按需建表；不改现有入库、任务、任务产出、工时、派工和绩效表。新日报不合并进 `v2_ops_job_results`。
- 原子 D1 batch 在版本匹配时追加审计并替换当日值；任一数据库写失败整批回滚。重试返回当前有效值，旧请求不会回滚后来的更正。
- 仅测试环境且启用 SOP 升级时可用。管理员或有进口权限的派审员可以读写；日当派审员还要求当前授权有效、包含进口。沿用现有现场登录、签到、撤权、同源保护；不能用请求JSON伪造身份。
- 办公室API写入也必须通过现有操作姓名确认；不会将办公室手填姓名当成新增个人身份。新页面只装载在现场 `/001/`。
- 不改原 `001/app.js`、`001/index.html`；通过独立共享模块安装菜单和页面。与并行库内需求的交叉文件仅为 Worker 入口、权限白名单、办公室操作审计守卫和构建脚本的小范围接入。

接口：`sop_import_daily_scan_get` 接受 `business_date`、可选 `before_version`；`sop_import_daily_scan_save` 接受明确的 `business_date`、数值类型 `total`、读取得到的 `version`（首次0）和 `client_req_id`。成功返回当前值与 `saved_version`；版本冲突409、非法输入400、权限不足403。查询返回 `efficiency:null`、`efficiency_status:"scope_unconfirmed"`。

## 工时口径调查

当前实现只完成日报闭环，不计算人效，也没有确认数量单位。用户尚未确认“过机扫描作业人时”还是“整个进口组作业人时”，以及扫描量是不是包裹件数；父任务已提问。

| 现有数据/代码 | 可支持的事实与限制 |
| --- | --- |
| `v2_ops_job_workers` 的 `worker_id/joined_at/left_at`，结合 `v2_ops_jobs.job_type='scan_pallet'` | 能识别已记录的逐人过机扫描参与时段；可以按 KST 日界切分已经可靠闭合的跨日时段。不能证明所有扫描人员都已计时，也不能直接认定未结束时段是完整下班工时。 |
| `native-lifecycle.js` 的 `pauseNative` | 暂停会关闭个人作业段，恢复新建段，暂停空档不应计入。日报录入不会触发暂停、结束或恢复任务。 |
| `attendance.js` / `attendance-time.js` | 已有按签到范围、休息、身份和跨部门冲突核算的个人实际作业时间；在岗时间、休息、未分配时间与进口实际作业时间分别保存。当前汇总按部门，不能直接把进口总分钟标成“扫描工时”；跨日未签退、无当日身份关联会标记待核实。 |
| `dashboard-time.js` | 已有按 KST 区间裁剪个人段的函数；单纯求和仍需要解决同人重叠、非法时段和记录完整性。 |
| `v2_dashboard_order_list/export` | 按任务 `created_at` 筛选日期，并累加整任务工时，不是准确的当天人时分母，不能直接复用。 |

建议确认口径后展示“已记录扫描作业人时”，单位“人时”。计算时逐人取当天有效扫描时段，剔除暂停/休息并处理同人重叠与身份冲突，再累加不同人员真实时长；不乘人数、不按人数平分。跨日只算与当天 KST `[00:00,次日00:00)` 的交集，不能按任务创建日或完成日把全段归到一天。缺失、异常或未核实的开放时段要提示待核实，不能补成0或默认八小时。

数量与工时范围一致、记录完整且分母大于0后，才适合显示“扫描量/扫描作业人时”；若用户选择全进口组，则明确标为“扫描量/进口组作业人时”。只有包裹件数确认后单位才是“件/人时”；若实际是扫描次数，应为“次/人时”。日报数量只取该日最新有效值，不能再加每任务扫描结果。有效0数量且可靠正工时可以得到0效率；缺数量/缺工时/零分母均应显示不可计算。
