## 运行方式

先在业务候选目录执行 `node worker-v2/build-sop-staging.mjs`，再从本脚本所在目录运行：

```bash
CK_SMOKE_ROOT=/workspace/ck-ui-overlap-audit-1013 \
CK_SMOKE_OUT=/tmp/ck-ui-entry-smoke-candidate \
node tests/ui-entry-smoke-browser.mjs
```

`CK_SMOKE_ROOT` 决定 Worker、staging-entry、D1 schema、operator fixture 和 built assets 的来源；不替换成默认 main。所有浏览器请求仅允许同一 localhost origin。数据库为 SQLite 内存 D1，R2 为内存 map。管理员、派审员、日当、长期人员、作业及各单据全部为合成数据。

## 基线复现

基线 `3a4d9d9a87859115150cba9d11c742b904d30130` 实际复现四次失败：PC 1440px、手机 390px 各延迟 `sop_check_for_batch` 和 `sop_issue_adopt`，请求等待期间切换到作业计划；放行后可见作业筛选由 1 个降为 0 个。旧详情仍隐藏，JS 无异常，业务表不变。截图明确显示当前作业计划区域被清空。

复现命令：

```bash
CK_SMOKE_RACE_ONLY=1 \
CK_SMOKE_OUT=/tmp/ck-ui-entry-smoke-race-baseline \
node tests/ui-entry-smoke-browser.mjs
```

脚本保存四次断言的前后截图与 `result.json`，最终以失败退出，避免把风险推测当成已复现结果。

## 未验范围

- 浏览器是 Chromium 的 1440px 和 390px 视口；实体 iPhone、Safari、摄像头和扫码枪硬件尚未实测。
- 此脚本只检查打开、模式和导航生命周期。派工、作业保存、库存、附件上传、作废恢复、记账、打印、签到和签退等写操作由各专项测试验收；本脚本没有提交这些动作。
- 物料后台使用合成空库存；现场物料领用、归还、收货入口未在此脚本验证。
- 旧历史核对兼容、失败重试、附件与角色权限的完整行为由主任务迁移／问题点／核对专项验收覆盖。
- WMS 导入、管理看板、现场反馈、按单操作和全部现场作业类型未在此脚本遍历；现场反馈页面未修改。
- 这是候选本地验收，未由本任务部署，不能代替 Cloudflare 部署终态或线上真实业务验收。
