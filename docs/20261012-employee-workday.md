# 职员当日工作明细

范围：基于 `8760e1adc624f46aaffd3bd3ccd51364e8a131be`，仅 PR #7 测试分支与独立测试站。使用合成人员、内存数据库和实际构建页面验收；不修改考勤、历史业务或绩效分数。

## 数据来源与统计口径

职员身份使用 `ck_employee_profiles.person_id → ck_attendance_people.id`。本人作业使用其完整 `EMP-*` 工牌与 `v2_ops_job_workers.worker_id` 精确关联。姓名不是归属键，同名职员分别统计。

| 指标 | 真实来源 | 口径 |
| --- | --- | --- |
| 当日已派单 | `sop_events` 的首次 `sop_native_start`、`sop_task_create`、`sop_task_dispatch` 事件，关联 `sop_records` 的 task/dispatch 和实际作业 | 事件 actor_id 必须等于职员 person_id；按韩国日期及任务去重，不将需求镜像事件、人数、调整、暂停、恢复或旧任务接续计为新派单 |
| 派出任务当前状态 | `v2_ops_jobs.status` | 展示读取时点的进行中、已完成、已取消等状态；不能使用可能未随原生结束同步的派工 JSON 状态 |
| 跨日仍在途 | 此前的可靠派工事件与当前任务状态 | 独立说明，不能增加所选日期新派单数 |
| 本人参与及工时 | 当天有效签到区间内的本人原始作业段 | 任务去重，多个参与段不变成多单；有效时间沿用考勤区间、实际休息和冲突规则 |
| 参与任务中现已完成 | 当天本人参与的任务及当前状态 | 是参与过的任务已完成，不表示本人独立完成或当日个人产量 |
| 审核 | 有可靠 actor_id 的明确审核事件 | 保留实际审核时间及结论，排除需求/任务镜像重复；不将一般结束操作推断为独立审核 |
| 制单 | 有可靠 actor_id 的创建审计或明确创建事件 | 仅展示系统可确证归属的记录，不通过 created_by 姓名推断身份 |

所选日期按 KST 的 `[00:00, 次日00:00)` 划分；任务当前状态以页面读取时间为准。业务单号、客户、类型及数量来自原任务与关联业务单。团队实收或产出明确标为任务整体数量，不当作个人产量，也不除以人数。

审核任务数按任务去重，审核操作数保留同一任务退回后再审核等真实操作；分组审核的需求/任务双事件只计一次，最终收尾不再加一次审核。本人新建单据不包括仅被扫描或关联的拣货单、旧出库单。创建时间依据保存的单据/链接时间核对，审计稍晚落库不会漏算，也不放宽时间容差来认定旧单。单据数量标为当前参考；成果保持明确记录的零数量、箱、托以及打包、贴标、分组等独立口径。

## 记录范围限制

现场登录的事件 actor_id 使用登记职员的唯一 person_id，可可靠关联。办公室共享账号通常使用 `ck-office-admin`，操作姓名是手填业务标签，没有职员外键。不能把共享管理员、系统事件或同名操作标签归给某名职员。缺少可靠身份或未记录的审核、制单信息必须明确提示；没有已归属记录不代表职员没有工作。

## 页面与权限

`/shuju` → 职员 → 每日出勤显示紧凑当日作业摘要，姓名旁直接提供工作明细入口。手机出勤行以卡片显示，保留上下班、出勤时长、休息和负责人核实补卡入口。工作明细使用独立弹窗，不追加到长页面底部。

“当前现场作业”的未分配筛选表示目前没有现场参与段，不表示全天无派工或管理业务。列表摘要和详情均仅读取真实记录，不改变考勤或绩效。详情沿用办公室报表角色边界，现场和签到点会话不能通过直接请求读取其他职员工作明细。

列表按日期批量查询，不能逐人查询全套业务。详情按指定日期及职员读取；日期切换、关窗和迟到响应不得串人或覆盖新页面。弹窗打开时暂停自动刷新，关闭后恢复；查询失败不抹除已有汇总。

原 `/shuju` 入口会为所有办公室角色启动负责人专用的旧看板请求，导致有效只读会话被其 401 锁住。现在仅负责人启动该看板，其他已获报表读取权限的角色直接进入职员/日当报表；后端权限和会话 401 处理未放宽。测试中确实过期的只读会话仍退出并显示重新登录提示。
