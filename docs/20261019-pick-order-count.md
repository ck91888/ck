范围：测试分支 `upgrade/sop-safe-rollout-20260917`、测试 Worker `ck-v2-api-sop-staging`、`sop-test.ck91888.cn`。基线已核实为 `1577aaf6633ed29ba8a08a06218f34523673f04c`，保留此前混合单位出库、附件拖拽及性能修改。无迁移、历史回填、真实单据操作、凭据配置或生产发布。

## 字段与数据口径

入口：`现场执行 /001 → 代发拣货 → 分配人员并开始 → 本次拣货计划工作量`，新增 **订单数量 / 주문 수**。指本次整任务覆盖的订单数；产品总件数、SKU种类数、涉及货位数及叉车是／否沿用原含义和交互。手机使用 `inputmode="numeric"`。

存储在既有 `sop_records(kind='dispatch', id=job_id).state.planned_pick_workload.order_count`。该嵌套键与大货批次和装货接口的顶层 `order_count` 分离。前后端只接受正安全整数（1～9007199254740991），新建及已登记但未开工的拣货任务必填，与原开工事务、审计和幂等请求一起保存。

一个任务只保存一次，不按参与人数乘、不复制到每张拣货单或每个人实绩；暂停／恢复、换人和完工保留原值。其他任务入口不增加此必填项。
