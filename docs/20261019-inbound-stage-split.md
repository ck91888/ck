# 代发理货、上架分阶段验收

仅用于 `upgrade/sop-safe-rollout-20260917` / `ck-v2-api-sop-staging`，基于 `a4270e3be239bc26c5ce10358958a60a2bc8e23a`。不合并 main，不修改正式配置或真实业务记录。

## 行为

- 现场代发入口拆成“理货”“上架”，均走原有人员派工、主操作员、预计时间、实际人员计时、暂停/恢复和权限校验。
- 理货保留原有全部字段：本次入库（按原计划数量类型）、理货数量、贴标数量、修补箱数量、其他操作说明、入库说明、其他备注。空值/0 的原有口径不变。
- 上架完成才填写实际货位数（必填，0–100000000 的整数）和是否使用叉车（必须明确选择是/否，无默认选择）。每个任务保存一份共享结果，与人数无关。
- 状态按外部单号推进：理货中 → 理货完成待上架 → 上架中 → 已入库。协同中心详情、筛选及导出同步新状态。到仓、卸货及混合快递收齐的前置条件保留。
- 理货时累计本次入库数量；上架不再接受数量累计。协同中心显示上架货位与叉车结果，入库计划 CSV 增加货位合计和逐单叉车明细，数据看板作业摘要也显示上架产出。数量不按工作人员重复相加。
- 多单号、混合代发/大货部门各自完成。部分理货或上架完成不结束整张计划；作业计划的实际上架日期取上架完成结果。

## 兼容与事务

新增任务类型 `inbound_direct_tally`、`inbound_direct_putaway`；原 `inbound_direct` 历史合并任务沿用原完成合同，不补造任务、不强加新字段、不改写原产出或工时。大货理货上架和退件会话不拆分。

新增数据库索引/触发器只保护新阶段：独立阶段唯一性、上架前必须理货完成、禁止新旧任务重叠、禁止移除/换部门已理货单号、禁止从其他完结入口跳过上架。开工、人员登记、阶段结果、数量、工时、部门与计划状态在原事务边界提交；失败回滚，可用同一请求重试。暂停任务仍占用本单号并阻止提前完结。
