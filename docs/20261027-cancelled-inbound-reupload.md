# 已取消入库携带未派工作业要求时重新上传

仅测试分支 `upgrade/sop-safe-rollout-20260917`、Worker `ck-v2-api-sop-staging` 与 `sop-test.ck91888.cn`。基线为 `19371bfb65c899f27683676dfc0a397e8f254429`，保留韩国时间凌晨 04:00 系统收尾和既有人员占用修复。未修改正式配置或 main。

## 原因与最小复现

用合成客户、快递运单和作业要求创建入库计划，取消该计划后以相同内容再次创建。原基线报“已关联……请先核对 / 이미 연결된 송장번호”。普通取消计划的快递复用已存在，但 `reusableCourierPlan` 将所有未取消的 SOP 作业要求都视为执行证据；入库取消没有同步关闭尚未派工的作业要求，因此仅有计划资料也会阻止复用。

无作业要求的普通取消重建不受此次缺陷影响。尚有效的计划仍须拦截重复。未读取或改写用户真实记录，不能将合成复现表述为已核实某张线上单据的全部关联。

## 修复与数据保留

预检与写入事务共用同一安全条件。取消计划关联的作业要求只有处于 `pending` 或 `cancelled`、没有任务编号、成果、出库关联或分组执行证据时才允许复用。记账、强制完成、实际卸货/上架、历史任务/工时/成果、任何关联出库等原有保护继续保留。

重传事务先为尚未派工的原作业要求追加 `sop_inbound_replaced` 审计，保留完整变更前后快照和替代入库编号，再将原要求封存为取消。原入库行、原作业要求、附件、创建事件、取消原因和已收货事实保留；快递关联沿用现有不可变历史表。新建及关联释放、旧要求审计与封存作为同一事务提交，任一步失败则全部回滚。

不创建库存、现场任务或出库订单；不批量迁移、清理或删除历史记录。
