# 新现场照片上传前压缩（本地候选）

基线 `7f448cf3af84b89dd65b07d5dff05244f63f9dbe`，来自测试分支 `upgrade/sop-safe-rollout-20260917`。发布标识 `20261030-photo-upload-compression`；本地验收完成，尚未推送或部署。发布结果须按最终远端 SHA 对应的 Cloudflare 成功检查确认。

## 范围与行为

- 专用照片入口：001 现场问题处理、车辆照片；002 问题详情照片及新建问题的拍照/照片按钮；卸货到货照片；作业审核货位照片。
- 新建问题的通用拖入资料、文档选择，以及作业需求的标签、箱唛、出库单等资料附件保持原文件。旧照片、旧数据库和存储对象不修改，无数据库迁移。
- `shared/photo-upload.js` 在浏览器端串行检查并压缩，长边候选 2048px、JPEG 质量 0.86；没有体积目标或反复降质循环。小图不放大，处理结果较大则保留较小的输入字节。透明 PNG/WebP 输出 PNG，保留透明。动图、HEIC/GIF 等不支持格式或损坏图片明确阻止并提示重新选择，不会偷偷上传未处理的大原图。
- 按文件签名识别格式并统一最终 MIME 与扩展名；处理 JPEG EXIF 1–8 方向。正常解码像素上限 40MP，已报告低内存的设备上限 16MP；不支持 ImageBitmap 的后备路径也限制到 16MP。超出时提示在相册先缩小，避免盲目全尺寸解码。内存不足/编码失败可重新选择或重试。
- 最终 File 在选图处理阶段生成并缓存。新建问题草稿和卸货重试保留原请求身份及相同字节/文件名；权限、所属、服务端哈希校验和幂等规则未改变。原 File 仅保留在本次页面会话中供失败恢复，不另传或持久保存原件。
- 专用旧上传入口增加进度、暂停后续照片、手动重试与移除待上传照片。暂停不会中断已经发出的写请求；恢复继续使用已编码 File。原生反馈弹窗关闭、重开或重渲染时，恢复控件会保持可见。没有自动重试写请求。旧通用照片上传接口原本没有服务端幂等键，结果不明确时要求先核对已保存照片；本轮没有改变该协议。
- 页面提示只保存处理后的照片；查看/下载及异常提示的中韩文均使用“照片”，避免暗示另有拍摄原图。
