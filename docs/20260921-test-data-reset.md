# 测试数据清空与管理按钮

用户要求清空原测试数据，并新增可自行使用的清空按钮。

## 使用

测试系统首页下方「测试管理 → 清空测试数据」。负责人点击后可核对入库、出库、任务与签到数量，再点「确认清空」。中韩文提示会显示进度及完成结果。中断后重新打开首页，可继续同一次清理；不会自动开启新一轮清理。

范围包括入出库计划、作业需求、现场任务及产出、签到与工牌、工时与休息、问题反馈、核对、导入记录、耗材与物品及采购流水。账号、人力公司选项、库位、数据库结构和系统设置保留。

## 边界与恢复

- 仅独立测试站域名、staging 标志、明确功能开关及指定测试库标识同时匹配时启用。正式配置和正式入口没有更改。
- 复用现有负责人身份验证。当前测试站本来就是免授权码测试模式，因此所有测试站访问者具有测试负责人身份；切回个人登录后，按钮与接口均要求 manager。
- start/step 接口只接受同源 JSON POST、专用请求头及明确确认值。GET 不能删除数据。
- 每次清理先在 D1 内逐表创建 `ck_backup_<run_id>_<table>` 备份，再删除原表数据。备份、删除及进度标记在同一事务内。备份不公开返回，R2 附件原文件保留用于恢复。
- 每次请求最多处理 4 张表。计数使用分组标量子查询，避免 D1 的复合 SELECT 限制。清理期间阻止其他业务请求，保留登录入口供负责人恢复进度。
- 请求幂等键、单活动清理约束和逐表标记防止重复清空。已完成的旧请求不会删除后续新上传数据。最终核对若发现清理期间的意外新增记录，会停止并保留，交由维护人员核实。
- 清空前的备份需要维护人员按清理编号恢复；普通页面没有直接访问备份的入口。不要直接把备份表改名替换原表，原表约束和索引必须保留。
