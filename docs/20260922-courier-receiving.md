# 到仓快递：点选归属、扫码收货与入库联动

## 业务依据

按用户提供的《仓库入库记录》Sheet1 C:J 表头设置 8 个归属：8-1、8-2、8-3、8-4、천막동（篷布仓）、仓库耗材、采购物品、无法识别件。历史表格仅用于提取表头和格式，不导入历史记录，不提交原始表格或历史单号。

SOP 3.4 的职责是外包装收货、整理、归类和交接；先检查耗材／采购登记，再确认归属。扫码不替代实际理货、退件操作或采购库存入账。无法识别件单独归类，由办公室核对。

## 操作与联动

- 现场执行 → 快递收货。所属使用八个点选按钮，初始不选；选中后高亮并聚焦单号，连续扫码保留本次所属。更正归属也使用按钮。手机每行两个，电脑每行四个。
- 默认记录当前登录人；可用已签到且未签退工牌切换实际扫描人。保存首次入仓时间、扫描人、登录人、归属；重复扫描保留首次记录，不重复计件。
- 协同中心 → 到仓快递。按所属、单号、韩国日期、交接状态查询；每页 50 件。更正归属需要原因，交接需要接收人，保留版本与操作历史。
- 入库计划货物明细新增“快递”，每行一个单号，一张计划填写在同一快递行。按不同单号自动计算计划数量，不能跨计划重复绑定。计划详情显示逐件到仓进度，打印包含快递单号。
- 用户确认：理货上架的快递收齐后仍须逐个完成关联外部入库单；其余类型收齐即可已入库。混合车辆货物与快递的计划需两条收货路径均完成；快递实收数只从扫码记录计算。
- 收货先于计划时，后补计划也能按单号关联。已收货计划锁定修改，避免删除到货对应关系。
- 手工完结接口不能绕过尚未收齐的快递。快递收货不伪造现场任务或工时；清空测试数据时包含快递记录与关联表。

## 防误扫边界

允许完整 11～14 位数字、LP/EZ + 9 位数字 + CN、JJD + 18 位数字；规范化全角、空格和连接线，拒绝网址、备注混入和其它格式。相机只启用 Code128、Code39、ITF、Codabar 一维码，不启用 QR、EAN、UPC。

格式校验不能识别所有同长度、同字符构成的非运单条码。扫码枪/PDA 仍需在硬件端限制不需要的码制；本次未验证实物设备解码效果。生产规则若要新增格式应先核实真实运单样本。

## 设计

沿用系统森林绿 #17594c、深绿文字 #163e37、浅绿反馈 #e4f0e9，异常使用暖橙 #fff0e7；中文和韩文并列，继承现有系统字体。现场以所属按钮、单号输入、即时结果为主；办公室用紧凑表格与单行筛选，详情在对话框展开。按钮至少 56px 高，选中态及键盘焦点均可辨认，无需图像资产。

## 验证

`node --test tests/*.test.mjs`：89 通过，0 失败，5 个既有可选浏览器用例跳过。新增集成验证涵盖格式、幂等、归属冲突、交接审计、权限、跨计划冲突、先收货后建计划、混合车辆到货、采购优先、多外部入库单和手工完结保护。

本地真实页面操作：新建含两件快递的直进直出计划；点选 8-2；第一件 1/2 保持未完结，第二件 2/2 已入库；办公室显示单号、归属、时刻、扫描人及计划链接；手机 390px 下验证两列按钮及重复扫描不计件。纯快递计划隐藏旧的车辆卸货提示，避免与到仓进度矛盾。
