# 全界面整理与签到接入

范围：独立staging、原001/002/003/shuju及新签到页。用户已认可签到样稿并授权全部测试界面整理。不开生产开关，不合并main。

## 设计计划

沿用已认可的固定签到点风格：环境底#EEF3F1、纸面#FFFFFF、正文#223C36、主操作#18564A、分隔#D1DED8、待核实#976315。状态红绿只表达结果，不把正常完成设成危险操作。中文Microsoft YaHei、韩文Malgun Gothic，主文16px，手机主按钮至少48px。

全系统共用明确模块导航、页标题、查询筛选、列表、详情和表单样式。001手机/PDA单列，以扫描和本单动作为主；002与003桌面展开表格和分区资料；shuju表格数字对齐、个人明细可追溯；签到电脑保持简洁，不展示全员财务记录。

```text
系统导航：现场执行 | 协同中心 | 耗材物品 | 数据看板 | 上下班签到
模块标题                     当前身份 / 语言
本模块业务标签
筛选 / 扫码 / 主要动作
列表或单据详情
```

审视并删掉无关装饰：不用营销大标题、背景渐变或满屏重复卡片；有真实分组才用面板。手机长工作流程放在页面内，短修改才用居中弹窗。既有模块入口保留，修正扫码和任务之间重复制单的路径。

## 界面改动的视觉验收（2026-10-12 起）

用户明确要求后续持续注意排版。功能测试通过不等于界面可交付；每次修改受影响页面后，必须打开实际构建页面、生成截图并逐张查看，不能只检查 DOM 或 overflow 数值。

- 桌面至少检查 1440px、1280px，分别检查 100%、125%、150% 浏览器缩放；手机检查 390px、320px。记录真实 CSS 视口、缩放比例与截图尺寸，不能用图片缩放代替浏览器缩放。
- 列表与明细/编辑弹窗都要检查。使用包含长姓名、长部门、长业务标签、空状态和多项记录的隔离合成数据；真实点击主要入口、关闭及取消操作。
- 查看表头与内容对齐、数字层级、普通行高、空白密度、按钮一致性。检查旧 `nth-child`、全局表格字号及内边距规则是否覆盖新组件，不能仅靠新增样式猜测结果。
- 中韩文必须有明确主次层级，短标签可分别占一行，韩文词语不拆成孤字；按钮的每种语言均应保持完整。保留页面已有语言切换方式或双语模式，不擅自删掉韩文。
- 数字摘要使用短标签，长统计口径放在可发现的说明或明细内。缩短文案不能改变业务含义，参与任务完成数不能写成个人产量，缺少记录不能写成未工作。
- 窄屏使用卡片或适当重排，不能硬挤桌面宽表。检查页面、卡片、弹窗和截图本身都无横向裁切；长日期、工号及任务号要有合理换行，不能覆盖按钮。
- 交付时说明实际看图发现并修正的问题、最终效果和未覆盖项，附可读取截图；不能仅汇报测试数量。

## 数据原则

日当名单来自当天考勤，工时来自原个人参与时段。长期固定牌每日签到、临时牌带日期；公司更正保持工号和签到时间。实际休息明确记起止，不按固定午休扣。下班停止本人时段，留待核实，不结束多人任务。工时不按人数均分。未归属、跨部门重叠和跨日遗留明确列出。
