## 工时、数量及边界

- 用户输入结束日期含当天。例如开始 `2026-10-12`、结束 `2026-10-18`，计算区间为 KST `[2026-10-12 00:00, 2026-10-19 00:00)`，即 UTC `[2026-10-11T15:00Z, 2026-10-18T15:00Z)`。
- 以真实人员 joined_at/left_at 与区间交集计时，整数毫秒累积后展示分钟/人时；不使用累计分钟代替期间工时。跨日按KST拆分，暂停间隔不计，区间前建单的本期作业纳入。
- 未结束段默认排除、不推测离岗时间；已结束但晚于显式截止时点的段截到截止时点并标暂算。导出携带同一个截止时间。
- 同一可靠工牌的重叠区间显式告警，保留各任务记录时长，不擅自分摊或扣除；不同人员并行照常累计。`overlap_seconds` 是受重叠影响的各段时长之和，不是可直接从总工时扣除的值。分日导出的原始段重叠值不能跨日再次累加。筛选外任务的同人冲突仍会检出。
- 缺人员分段、无效日期、未结束、数量缺失、来源冲突等列为待核。没有分段的候选仅按明确完成时间或更新时间定位，绝不把累计量伪装为精确周工时；完全无日期证据、且不在候选范围内的缺失无法追溯。未归属部门/支持工时不表示闲置。
- 任务累计数量、本期完成任务的累计数量都不等于本周内生产数量，不按工时比例分摊。只有完整时段均在区间内、完成时间明确、没有异常/缺口、未按个人筛选的任务，才进入同部门、工种、指标、单位、盘点类型和记录时点的同类样本。开始快照和单位未记录的指标不计算效率。现有记录本身无法证明绝对没有遗漏，因此样本只代表可核对记录。
- 数量按任务统计，不乘参与人数或关联入库单数。客户仅复用真实已存关系（含多单上架）；部门按已存派工归属/业务记录，不按姓名或客户猜测。
- 进口日报的扫描/全组分母及业务单位尚未确定，本次未新增或决定其人效公式。管理看板原WMS匹配仍属旧参考功能，通用工时改为区间交集、未结束排除并提示重叠。

## 使用及真实周数据

1. 登录测试站数据看板 `/shuju/`，在「单子数据」保留默认「按实际作业日期」，输入 `2026-10-12` 至 `2026-10-18`。可筛选用工部门、工种、状态、单号或人员；人员筛选只计该人员工时，任务数量仍是整任务，不能配成个人产量。
2. 查询并下载「导出明细 CSV」：包含任务ID、区间秒数、累计结果、是否本期完成、可比性及完整JSON。「导出同类数量样本」按单位和指标分组。
3. 到「工时分析」使用相同日期/部门/工种筛选，下载「导出明细 CSV」取得人员分日时段。用任务ID对账，按秒数核对任务、部门、工种及人员汇总。缺分段任务只出现在任务/缺口统计，无法归入具体人员。
4. 工时导出使用最近一次成功查询的筛选、截止和快照；订单导出按当前筛选开启新查询，文件每行说明口径、区间、截止及快照。跨页源数据变化即失败，要求重查，不生成部分文件。

当前执行器没有可用、获准直连的线上业务读取路径。测试域名曾被HTTPS CONNECT 403拒绝，本轮不重试或绕过；受限Library旧附件及其本地副本均未读取。最小用户操作是在已登录的测试站下载上述三个新CSV，通过获准可读的渠道交付。没有真实新导出前不声称已重算上周报告；业务数据不提交公开仓库。

## 性能和完整性

每页最多200行。实际查询最多31天、区间时段20000条、候选任务5000项、相关任务累计人员/结果各20000条；超限明确失败并要求缩小日期/范围，不返回部分汇总。跨页导出最多30000行/30MB；单页响应8MB超限时导出自动减小页长，单条仍超限则报错。旧建单导出也分页，详情超过20000行明确报错。原始JSON不再字符截断。

SQL按区间取有界候选、使用JSON ID集合批量查关联，无逐任务远程N+1。仅装饰当前页业务单号，前端查询不一次拉全表。为保证全量汇总、跨任务重叠及分页一致性，每页会重新计算有界区间并校验快照；大区间请按天/周分批。历史记录不断变化时需在相对稳定时导出。截止时间是计时截止，不是历史数据库版本回放。
