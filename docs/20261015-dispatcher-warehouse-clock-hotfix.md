# 2026-10-15 派审员本人仓库整理的占用校验热修

基线：测试分支 `upgrade/sop-safe-rollout-20260917`，`c6907e11928a13eb8b2598ca5c95456423d14dec`。本热修独立于“一人多单”开发，不改变多任务并发规则。

## 查证与修复范围

当前忙碌校验查询实际操作工时段，不查询 `owner_id` 或派审员身份。合成 API 和真实页面均验证：负责人给两名员工分别派拣货任务后，本人可以开始仓库整理，原有派审权限保留。

确认存在另一种可复现的假占用：本人历史任务已经完成、首页不再显示，但遗留 `left_at=''` 的工时段；新开仓库整理会返回与现场相同的“已在另一任务，请先办理交接”。不能只凭两张截图证明现场具体是哪条历史段，本次没有查询或修改真实业务记录。

热修在已授权、已签到的本次实际操作人员通过出勤校验后，仅收口其所属任务已明确完成、且具有合法 `finished_at` 的遗留工时段。按原任务完成时间结束，不使用当前时间、最近更新时间猜测结束时间。保存原段值、原分钟、结束时间及修复操作身份到 `ck_completed_clock_repairs`。已完成任务、产出、单据、作业人员分配、派审归属均保留；原来的两张在途拣货任务不变。

仍在实际作业、休息中、已签退或历史结束时间不明的人员继续按原规则拦截。实际占用错误增加作业类型和已有公开单号；无法可靠收口的已完成记录会明确提示核实原任务。没有全局放开一人多任务。
