# 日当人力与职员作业状态验收

基线：PR #7，`9ad72c065326133977025c3e6420bf9de4604150`。发布标识：`20261008-workforce-dashboard`。仅测试分支，正式版与 main 不变。

## 日当人力

- 当天管理部门可标记为大货、代发、进口或未标记，并与公司、姓名、当前作业状态组合筛选。此标签逐日保存，与真实作业段的用工部门独立；修改标签不改历史任务、考勤时间或工时。
- 当前未分配筛选依据实时 `status=unassigned`，不依据当天曾累计的未归属分钟；休息、作业中与已签退分开显示。
- 误签到、重复签到可由办公室负责人填写原因后删除。采用可恢复的作废标记，保留原记录、工牌、日期、上下班时间与完整审计。作废记录不计入正常名单、人数、公司汇总、未签退提醒或正常 CSV，可从“显示已删除签到”恢复。
- 当班已有作业段、休息记录或未完成借调时明确阻止删除。不会停止任何作业或删除合法工时，也不把作废伪装成签退。删除与并发开工、休息、借调双向数据库约束；跨午夜作业也受保护。长期工牌其他日期的合法签到仍可使用。
- 作废工牌不能继续查询打印、补卡、更改公司、签退、休息或派工；旧签到/打印请求回放亦不能显示未删除的旧成功状态。当日再次签到需负责人明确恢复或核实为同名不同人，不静默复活记录。
- 明细改为居中对话框，包含当天状态、任务、休息、修改/打印历史和阻止删除的原因。关闭、Esc、取消后保留列表筛选、滚动及焦点。

## 职员出勤

- 在所属部门旁显示当天实际作业状态及进行中的任务部门/单号。职员所属部门仍按职员资料显示，不能替代实际作业部门。
- 支持当前状态筛选，导出追加状态及任务列，不改已有考勤列。
- 新管理操作仅在办公室日当页面开放；现场与签到点不扩权，职员签到没有新增删除入口。

## 权限、审计与存储

- 当天部门标记允许办公室 manager/dispatcher，删除和恢复限 manager。版本号、请求指纹及事务保证重复提交或并发操作不能覆盖更新。
- 操作记录保留账号 ID，并保存服务器当前确认的操作姓名；旧页面姓名上下文失效时拒绝提交，忽略客户端伪造姓名。
- 测试环境惰性创建 `ck_attendance_management` 表与约束触发器，不改原考勤表的列结构、不批量修改既有记录。测试数据维护清单包含新表，原备份/恢复边界保持一致。

## 验证

使用完整当前分支业务代码、Node 24、内存 SQLite/D1 适配器及 jsdom；无线上业务记录用于测试。运行命令：

`node worker-v2/build-sop-staging.mjs`

`CK_JSDOM_MODULE=/tmp/ck-workforce-deps/node_modules/jsdom/lib/api.js node --test tests/*.test.mjs`

新增后端回归覆盖权限、部门和工时独立、删除/恢复、审计、相同请求回放、旧版本、并发新增任务/休息/借调、跨日工牌、跨午夜段、员工保护及正式开关。新增 DOM 回归覆盖筛选、导出、取消/Esc、焦点、重复点击、丢失响应重试、日期竞态、页面重建、关闭后迟到响应，以及员工状态与真实批量导入组件的同页共存。

实际 Chromium 云浏览器在独立演示服务验证：日当当前未分配筛选、当天标签更改、明细居中与 Esc、取消删除、删除后人数变化、恢复同一工牌和原始时间、进行中任务与休息的删除阻挡、职员实际任务和状态显示。桌面及约 485px 窄窗口检查。浏览器示例全部为虚构人物和任务。

最终完整回归 561 项全部通过，0 失败、0 跳过；构建和共享/Worker JavaScript 语法检查通过。实际浏览器补充验证后退/前进不残留弹窗，员工状态筛选只保留相应状态人员。部署结果见本次提交的 PR 检查。真实弱网、物理扫码枪/打印机、云端规模并发和线上页面均未用虚拟数据验证。
