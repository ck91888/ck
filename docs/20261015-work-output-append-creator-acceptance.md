# 2026-10-15 作业数量、追加预约及创建姓名验收

基线为 PR #7 的测试分支 `upgrade/sop-safe-rollout-20260917`，远程提交 `415da2e13ca2c10cb904463d69e44ed901e61f0d`，树 `83bb9cc8ade80aa19d0fa0a3ee18b1a6a6c8ff05`。实现和验收在独立工作树内进行，所有业务验收数据均为本机内存 SQLite、模拟 R2 和合成身份。批准的发布目标仅为 `ck-v2-api-sop-staging`。

## 行为

- 入库箱数用于到货核对。作业计划货量、各分组预计作业箱数和仓库实际产出分别记录；新建、保存及拆组不再要求预计箱数与上阶段相等。无需建立来源箱分配账，也无需客服额外按 SKU 拆单。
- 同一来源箱唛可用于多个作业组。各组的实际产出仍分别完成、审核；预填数不生成产出、可出库数量或已完成状态。
- 出库可用数量取已审核实际产出。未审核时显示待仓库完成并审核；实际产出的数量、单位、版本、重复分配、子范围重复占用及权限保护继续有效。已审核成果拆分仍须保留原实际数量合计并重新审核。
- 在“入库计划 → 本批作业要求 → 追加本批作业要求”中，已有作业、附件和出库计划保留原记录。仅追加作业可直接保存；本次确需新增出库时，可直接在本组填写，或把已填写的预约明确选择到所属资料组。缺少所属组时保留表单内容并提示选择，不要求删除重填。
- 作业计划列表、批次明细及单项详情显示“上传/创建”。使用该作业计划的创建审计和保存的登录操作姓名，不取关联入库计划创建人或最后更新者。历史没有可靠姓名时显示“未记录”。附件保留各自原上传来源。

## 验证

- `tests/cargo-create.test.mjs`、`cargo-groups.test.mjs`：一箱来源建立共用箱唛的上架/Coupang 两组，预计箱数与计划数独立，整计划货量可不填；普通资料组及文件权限继续有效。
- `tests/cargo-multi-reservations.test.mjs`：预填 10 箱并预约 40 箱时不伪造产出；实际审核 50 箱后可分配 40+10，继续分配被拒绝。实际少于预约时须按实际修正；来源一唛一箱不限制加工后的实际产出数量。
- `tests/work-output-independent.test.mjs`：同一来源箱唛的两组分别实际产出 20 箱、7 箱，独立审核和出库；重复/超量分配被拒绝且事务回滚。
- `tests/work-need-creator.test.mjs`：通过真实 Worker 登录和操作姓名确认，验证来源创建人、作业创建人、后续操作员不同的场景及历史缺失姓名。
- `tests/inbound-append-independent-browser.mjs`：真实构建页面与 Worker 验证原已完成作业、已出库计划、审计和附件逐字段不变；旧预约草稿归组、内容保留、响应丢失重试和双击只创建一次；手机仅追加作业不会新增出库；再次打开无旧草稿污染；入库内联表单也可明确归组。
- `tests/cargo-create-resilience-browser.mjs`：多卡隔离、上传失败重试、已提交响应丢失、离开页面和关闭窗口时取消草稿。
- 在 1440 和 390 像素宽度检查列表及详情，创建姓名可换行，文档没有横向溢出。合成截图由浏览器脚本生成于 `/tmp/ck-inbound-add-need-evidence/`，不包含用户原始截图或真实个人信息。

结果：全量 1075 项通过，0 失败、0 跳过；补充的共用来源实际产出专项 1 项通过。两项真实浏览器脚本均通过。

全量回归命令：`CK_JSDOM_MODULE=/tmp/ck-test-deps/node_modules/jsdom/lib/api.js node --test tests/*.test.mjs`。DOM 运行时安装在临时目录，不修改业务依赖。
