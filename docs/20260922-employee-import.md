# 职员资料批量导入

发布标识：`20260922-employee-bulk-import`，仍仅测试环境启用。

数据看板 → 职员出勤 → 批量导入，在原页展开预览；顶部及面板内均可下载 Excel 模板。

- 支持 Excel（xlsx/xls）与 CSV，首行姓名、工号、部门必填，状态可选。每次 1–200 人，文件最多 5MB。模板单元格提供八个部门及在职/停用选项，支持中文、韩文或双语名称。
- 工号是唯一键，必填，按英文大写统一；保留数字工号前导零。相同工号更新姓名、部门及明确填写的状态；状态为空时，新建默认在职，已有职员保持原状态。同名不同工号允许登记。文件内重复工号报错，不猜测应保留哪一行。
- 选择文件后显示逐行预览：新增、更新、不变、错误，更新行列出原值。存在任何错误不允许导入，显示原表格行号。改好表格后重新上传。
- 确认导入一次性提交所有职员资料与审计；网络重试保持请求幂等。预览后资料改变要求重新核对；事务内再次保护未签退/仍在任务中的职员不能停用，失败整批撤销。
- 保留已有人员 ID、工牌和历史出勤，不删除表格中未包含的职员，不自动签到。资料 CSV 导出可再次导入，用于测试清空后的恢复。
- 仅负责人可预览与导入，不改变登录账号、登录权限或每日出勤数据。

实现：`shared/employee-import.js`、`worker-v2/employee-import.js`，沿用职员资料/审计表；无新增迁移。模板由 `shared/templates/employees.xlsx.b64` 随构建发布到 `/templates/employees.xlsx`。

验证：职员导入、原职员签到与考勤相关 23 项测试通过，覆盖 200 人批量、重复/错误、旧状态和历史保留、权限、并发改动与事务回滚、实际模板经 SheetJS 读取、双语部门、CSV、前导零及公式拒绝。浏览器本地虚拟数据验证文件选择 → 2 人预览 → 确认导入 → 职员列表显示 → 重新核对为 2 人不变；界面截图已检查。此次不向线上导入虚拟人员，也不清空任何现有数据。

模板已用 Artifact Tool 导出、检查字段并通过实际解析器往返测试；Windows 运行时图片渲染无诊断退出，未生成 Excel 渲染预览。线上发布结果以 PR #7 的最新验证记录为准。
